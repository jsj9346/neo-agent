## 1. 언어: TypeScript — 왜 Python이 아닌가

두 레퍼런스가 서로 다른 언어(OpenClaw=TS, hermes=Python)라 어느 쪽을 골라도 절반의 참조는 언어가 어긋난다. 갈림길은 `ARCHITECTURE.md` §3.1(구)에 정리했던 대로 **UI 비중**이었고, 다음 근거로 TypeScript로 확정한다.

**1. UI/UX 우선 원칙이 언어를 결정한다.** 프로젝트 규칙(CLAUDE.md)이 사용자 친화적 UI/UX를 우선한다고 선언한다. TypeScript는 CLI → 웹 UI → 데스크톱(필요 시)을 한 언어로 간다. Python을 고르면 UI를 얹는 순간 어차피 두 언어 체제가 되고, 개인 1인이 유지보수하는 프로젝트에서 두 언어 체제는 그 자체가 비용이다.

**2. 가장 되돌리기 어려운 원칙의 참조 구현이 TypeScript다.** 확정 원칙 1번(§2.1 — 에이전트 코어는 전송 계층을 모른다)의 최고 선례가 OpenClaw `packages/agent-core/`다. 코드를 복사하지는 않지만(재작성 원칙), 경계 설계·이벤트 유니온·큐 기반 상태 머신을 같은 언어로 옆에 두고 대조하며 재작성할 수 있다는 것은 실질적 이점이다. 반대로 hermes에서 가져올 것들(승인 게이트 5계층, SSRF connect 직전 재검증, 압축 세션 분기)은 **알고리즘과 정책**이라 언어를 건너 재작성해도 잃는 것이 적다.

**3. 컴플라이언스 타입 강제(§2.2)는 TypeScript가 자연스럽다.** "근거가 공식 문서가 아니면 **작성 자체가 불가능**해야 한다"는 원칙은 discriminated union + 리터럴 타입으로 **컴파일 타임**에 게이트를 만들 수 있다. Python(pydantic)은 런타임 검증이라 한 단계 늦다. IDEA-002가 이 경로로 구현된다.

**4. 생태계가 필요한 방향과 일치한다.** MCP SDK 정본이 TypeScript다(Footprint Ladder 5단). 메시징을 공식 봇 API로만 쓴다는 원칙상 Telegram/Discord/Slack SDK도 TS가 1급이다. Anthropic·OpenAI 공식 SDK는 양쪽 다 있으므로 무차별. Python의 강점(AI/ML 라이브러리)은 로컬 모델 학습·추론을 할 때 의미가 있는데, 우리는 모델을 API로만 접근하므로 해당 없다.

**포기하는 것** — hermes 참조 코드와의 언어 일치. 단 위 2번대로, 잃는 것은 코드가 아니라 대조의 편의다. hermes에서 가져올 목록은 전부 정책·알고리즘 수준이며 `docs/hermes-agent-architecture.md`에 파일·줄번호로 고정되어 있으므로 재작성 원본으로는 충분하다.

## 2. 런타임: Node.js 24 LTS+, 빌드 스텝 없음

- **Node 24 LTS를 최소선**으로 한다. 개발 머신은 25.2.1로 확인. 24를 최소선으로 하는 이유는 두 가지가 24에서 안정권에 들었기 때문이다 — `node:sqlite` 내장, 네이티브 타입 스트리핑.
- **빌드 스텝을 두지 않는다.** `.ts`를 Node가 직접 실행한다(타입 스트리핑, 이 머신에서 동작 확인). tsconfig에 `erasableSyntaxOnly: true`를 켜서 스트리핑 불가능한 문법(enum, namespace, 파라미터 프로퍼티)을 컴파일 에러로 강제한다 — 어차피 셋 다 안 쓰는 게 현대 TS 관례다.
- 타입 검증은 실행과 분리해 `tsc --noEmit`으로 한다. 실행이 타입을 안 본다는 것은 검증 게이트가 별도로 반드시 있어야 한다는 뜻이다(CI·pre-commit).
- 폴백: 네이티브 스트리핑이 막히는 상황(데코레이터 필요 등)이 오면 `tsx`를 dev 의존성으로 추가한다. ~~번들링·배포 형태는 배포가 필요해질 때 결정한다~~ → **2026-08-09 확정** (`DISTRIBUTION.md`): 빌드 산출물을 만들지 않고 **링크 설치** 하나로 간다.
  > **이 절이 몰랐던 제약이 실측으로 드러났다.** 타입 스트리핑은 `node_modules` 아래의 실제 `.ts` 파일에 대해 **거부**된다(`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`) — 심볼릭 링크 경유만 realpath 해석으로 통과한다. 즉 "빌드 스텝 없음"은 **워크스페이스·링크 설치에서만 성립하는 성질**이고, npm publish는 그 자체로 빌드를 강제한다. 이 문서의 "빌드 스텝을 두지 않는다"는 그래서 배포 형태와 분리 불가능한 결정이었다(`DISTRIBUTION.md` §2.1).

## 3. pnpm 워크스페이스: 경계를 패키지로 강제

§2.1(코어의 전송 계층 비의존)은 규칙만으로는 지켜지지 않는다. **코어를 별도 패키지로 두면 의존성 방향이 `package.json`에 드러나** 경계 침범이 리뷰에서 걸린다. OpenClaw가 `packages/agent-core/`로 증명한 방식이다.

- 최소 구성: `packages/core`(에이전트 루프 — 의존성 목록이 리뷰 대상) + 앱 패키지(코어를 워크스페이스 의존으로 소비).
- 구체 레이아웃(앱 패키지가 CLI인지 웹인지, 몇 개인지)은 MVP 범위 결정(§2.8, 확정 — CLI 하나) 후에 잡는다. **스캐폴딩을 미리 하지 않는다**는 기존 결정 유지.

## 4. 스키마/검증: Zod v4

- 툴 정의는 결국 JSON Schema로 모델에 전달된다 — Zod v4는 `z.toJSONSchema()`를 내장한다. 스키마 한 벌로 런타임 검증 + 툴 정의 생성을 겸한다.
- MCP 공식 SDK가 Zod 기반이라 Footprint Ladder 5단(MCP)에 도달했을 때 마찰이 없다.
- OpenClaw의 TypeBox는 와이어 프로토콜 코드젠(JSON Schema → Swift)이라는 그쪽 요구에서 나온 선택이다. 우리는 다중 클라이언트 코드젠 요구가 없다. 생기면 그때 재검토한다.

## 5. 상태 저장: SQLite (`node:sqlite`)

- **내장 모듈이라 네이티브 의존성이 0이다** (better-sqlite3류의 빌드 문제 원천 차단). 이 머신에서 FTS5와 **트라이그램 토크나이저**(한국어 검색의 전제, IDEA-004) 동작을 확인했다 (SQLite 3.51.1).
- `node:sqlite`는 아직 experimental 표기가 있으나, API 표면이 좁고(DatabaseSync/prepare/exec) OpenClaw가 이미 실전 사용 중인 선례가 있다. 변경이 오더라도 흡수 범위가 작다.
- 쿼리 빌더(Kysely)는 **지금 넣지 않는다.** 스키마가 커져 raw SQL이 부담이 되는 시점에 도입을 검토한다. 스키마 경계는 2026-08-06 확정됐다(`SESSION-STORE.md` — DB 1개, 테이블 3개, raw SQL로 충분). ~~FTS5 도입 시점만 미결~~ → **2026-08-07 채택 확정** (`SEARCH.md`, 스키마 v3) — 실측해 둔 trigram 전제가 소비자를 만났다.

## 6. 모델 접근: 공식 SDK + API 키만

- 1차 프로바이더는 Anthropic(`@anthropic-ai/sdk`). 추가 프로바이더는 해당사 **공식 SDK + 공식 엔드포인트 + API 키**로만 붙인다.
- User-Agent·클라이언트 식별자는 neo-agent로 정직하게 보낸다. 이 원칙의 타입 레벨 강제는 IDEA-002 경로로 구현한다.
- Api/Provider 분리(OpenClaw식) 채택 여부는 스택 결정이 아니라 설계 결정 — 교체 지점은 `CORE-INTERFACE.md` §8(`ModelClient`)로 확정, 이원화는 보류(ARCHITECTURE §2.9).

### 7.1 브라우저 e2e 하네스 (2026-08-28 확정)

**이 절이 여는 물음은 「도구를 도입하는가」가 아니다** — 그것은 2026-08-28 인터뷰(`plans/20260828-k307-interview.md`)가 결정 ⑤로 이미 닫았고, 그 문서가 *"다음 사이클의 설계가 재논의할 대상이 아니다"*로 못박았다. 같은 인터뷰가 남긴 것이 이 절의 범위다: **§7 개정과 명령의 형태**, 그리고 미결 2 — *"분리된 브라우저 명령을 언제 부르는가가 안 정해졌다."*

**「문서가 실물보다 앞선다」에 걸리지 않는다.** 인터뷰의 비목표가 그 표현으로 이 개정을 이전 사이클에서 뺐는데, 그 문장이 겨눈 것은 **아직 안 정해진 것을 정해진 것처럼 적는 것**이다. 수단은 결정 ⑤로 정해져 있고, 이 문서의 지위 선언 자체가 *"스택 결정의 기록이지 어떤 패키지의 계약이 아니다"*이므로 설치 상태를 주장하지 않는다. 실물 설치는 실행 사이클의 몫이다.

#### 무엇을 재려고 도입하는가

**2026-08-28 실측이 근거를 산문에서 실물로 옮겼다**(`devnotes/20260828-devnote.md` §1.1). 매니페스트가 `/client/` 아래 다섯을 등재한 상태에서 실브라우저가 받아 간 것은 **하나**였다 — 형제 넷은 요청조차 나가지 않았고, 그런데도 **콘솔 에러 0·실패 요청 0**이었다(그 페이지가 낸 응답 총수는 셋이고 나머지 둘은 `/client/` 밖이다). `WEB-UI.md` §9.1의 집합 동일성은 파일의 실재와 등재만 보므로 「등재됐는데 아무도 안 여는 파일」을 **구조적으로** 못 본다. 그것을 보는 것은 실제로 받아 간 요청 목록이고, 그 목록을 내는 것은 브라우저뿐이다.

**시나리오의 정본은 `MILESTONE.md` C2다.** 여기 다시 적지 않는다 — 두 곳에 적으면 어긋나는 순간 어느 쪽이 정본인지 알 수 없다.

#### 결정

1. **수단은 Playwright이고 러너는 이미 있는 Vitest다. 새 외부 개발 의존성은 하나뿐이다.**
   - **`@vitest/browser-playwright`(브라우저 모드)를 안 고른 축은 비용이 아니라 «무엇을 서빙하나»다.** 그 갈래는 자기 개발 서버를 띄워 대상을 스스로 서빙하므로 재는 것이 `neo-agent serve`의 실물이 아니라 그 재현물이 되고, 바로 위가 든 도입 근거(매니페스트 도달 가능성)가 그때도 재지는지가 미확인이다. 딸려 오는 것도 실측됐다 — 정적 파일 서버 넷과 WebSocket 하나이고, 뒤엣것은 §2와 `WEB-UI.md` §2.1이 각각 제품에 대해 내린 확정과 읽기에 따라 마찰한다.
   - **`@playwright/test` 러너도 안 쓴다.** 러너가 둘이 되고 단정 문법이 둘이 된다. Vitest는 이미 이 레포의 도구이고, 이 배치는 OpenClaw가 실제로 쓰는 형태와 같다(아래 「레퍼런스 대비」).

2. **실행은 상시 게이트 밖이고, 타입 검사는 게이트 안에 남는다.** 인터뷰 결정 ⑤가 분리한 것은 **실행**이다. 하네스의 소스가 타입 검사 모집단 밖으로 나가면 그것은 분리가 아니라 무검사이고, 이 레포가 되풀이해 이름 붙인 「안 재지는 자리」가 하나 더 생긴다.
   - 그래서 **정적으로는 낡을 수 없고 실행만 사람 손에 있다.** 분리의 대가(아무도 안 부르면 조용히 낡는다)를 절반 회수하는 것이 이 결정이고, 나머지 절반은 결정 7이 진다.
   - 수단은 이미 선례가 있다 — 루트 `typecheck`가 오늘도 `tsc --noEmit`을 두 번 부른다(둘째가 `WEB-UI.md` §9.3이 못박은 브라우저 모듈의 별도 프로그램이다). 하네스의 소스가 루트 검사 프로그램에 드는가 별도 프로그램을 얻는가는 **세부**이고, 계약인 것은 **그 소스가 `pnpm check`가 도는 타입 검사의 모집단 안에 든다**는 것 하나다.

3. **자리는 워크스페이스 패키지가 아니라 루트의 별도 디렉터리다.** 갈래가 셋이었고 둘이 실물 근거로 죽었다.
   - **새 워크스페이스 패키지는 값이 안 맞는다.** 예산 게이트가 패키지 목록을 손으로 들고 그 목록과 실물 개수의 일치를 함께 재므로, 패키지를 하나 더하면 그 목록·버전 일치 검사·`WEB-UI.md` §2.2가 든 예산이 동시에 열린다. **검사 도구 하나에 그 값을 치르지 않는다.**
   - **`packages/serve/test/`에 못 둔다.** 하네스는 서버를 띄우려고 조립을 열어야 하는데, 그러면 `serve`가 `cli`를 개발 의존으로 얻어야 하고 그 패키지의 경계 테스트가 형제 개발 의존 엣지를 **정확한 수로** 단언한다. `packages/cli/test/serve.integration.test.ts`가 자기 자리를 고른 근거와 같은 자리다.
   - **남는 것이 루트의 별도 디렉터리이고, 그 배치가 분리를 덤으로 준다.** 상시 러너의 프로젝트 글롭이 `packages/*`이므로 그 밖의 디렉터리는 **원리적으로** 안 집힌다 — 분리가 파일 이름 규약이 아니라 **배치**로 강제된다. 규약이면 이름 하나를 잘못 붙이는 날 하네스가 조용히 게이트 안으로 들어오고, 그 실패는 게이트가 느려지는 것으로만 나타나 사람 눈에 안 보인다.
   - **대가를 적는다**: 그 디렉터리는 `DOC-CITATION.md` §6 U-b가 자리로 그은 `packages/*/test/` 밖이고 예산 게이트의 소스 순회 밖이다. 즉 **인용 계약과 임포트 예산이 이 디렉터리를 안 덮는다.** 이 절이 그 둘을 여기서 넓히지 않는다 — 모집단의 디렉터리 범위는 그 문서의 소관이고 이미 열린 물음이다. 적어 두지 않으면 다음 감사가 이 자리를 「누락」으로 읽는다.

4. **재는 대상은 조립 실물이고 모의로 두는 것은 모델뿐이다.** 서버는 이 레포의 조립이 실제로 세운 것이고, 소켓·자산·프로토콜·승인 레지스트리는 전부 실물이며, 자산은 `WEB-UI.md` §9.1의 매니페스트가 그대로 서빙한다. 브라우저도 실물이다.
   - **실 API로 도는 e2e를 만들지 않는다.** C2가 요구하는 승인 왕복은 도구 호출이 **결정적으로** 나야 성립하는데 실 모델에게 그것을 시킬 수단이 없고, 실 API는 키·과금·비결정성을 e2e에 들인다. `packages/cli/test/serve.integration.test.ts`가 같은 왕복을 모의 모델로 이미 결정적으로 돌리고 있으므로 새로 발명할 것이 없다.
   - **라이브 스모크와 다른 부류다.** 그쪽이 재는 것은 우리가 만든 SSE 픽스처가 실제 와이어와 같은가라 모델이 관측 대상이고, 키가 없으면 통째로 건너뛰는 것이 옳다. 이 하네스가 재는 것은 **화면이 실제로 도는가**라 모델은 입력일 뿐이다 — 그래서 건너뛰기가 옳지 않다(결정 6).

5. **포트를 0으로 받는다.** 서버 옵션이 이미 포트를 받고 바인드된 주소를 돌려주므로 하네스가 그 값을 브라우저에 넘긴다.
   - **이것이 `WEB-UI.md` §12의 세부가 계약으로 승격하는 것을 막는다.** 그 절이 포트 번호에 대해 *"기본값이 존재한다는 것이 계약이고 값은 아니다"*로 정해 두었는데, 고정 포트를 하네스가 쓰면 그 값이 하네스의 전제가 되어 계약이 된다. 2026-08-28 실측이 그 대가를 실물로 봤다 — 둘째 인스턴스가 `EADDRINUSE`로 죽고, 그러면 병렬·재기동이 새 계약을 요구한다.
   - OpenClaw가 e2e 워커를 하나로 강제하는 것이 같은 자리이고, **그쪽은 그 제약을 받아들였고 우리는 없앤다** — 우리 서버가 포트를 인자로 받기 때문이다.

6. **브라우저 바이너리를 설치 전제로 만들지 않는다. 부재는 skip이 아니라 실패다.**
   - **발자국이 어느 검사에도 안 잡힌다** — 2026-08-28 실측으로 크로미움·헤드리스 셸·ffmpeg 합계가 656 MB이고, 그것은 잠금 파일에도 pnpm 저장소에도 나타나지 않는다. 그래서 이 비용은 **사람이 알고 치르는 것**이어야 한다.
   - **명령이 그것을 조용히 내려받지 않는다.** 자동 확보를 명령 안에 숨기면 처음 부르는 사람이 656 MB를 모르고 받는다. 대신 부재를 **실패로** 내고 그 실패 문면이 다음 행동(설치 명령)을 든다 — `ARCHITECTURE.md` §2.6이 요구하는 형태이고, `WEB-UI.md` §3.1이 기동 거부에 대해 쓴 것과 같은 규율이다.
   - **건너뛰지 않는 것이 이 결정의 핵심이다.** 이 명령은 사람이 명시적으로 부르는 것이므로, 조용히 초록으로 끝나는 것은 *브라우저 없이 브라우저 검증을 통과했다*는 뜻이 된다. skip이 옳은 자리는 상시 게이트 안이지 여기가 아니다.

7. **호출 시점은 둘이고, 그 강제는 게이트가 아니라 작업 사이클이 진다** (인터뷰 미결 2의 해소).
   - ① **`packages/serve/`의 클라이언트·자산·서빙 표면을 만진 사이클의 검증 단계.** 그 셋이 이 하네스가 유일하게 재는 것(화면이 실제로 도는가·브라우저가 무엇을 받아 가는가)의 입력이다.
   - ② **마일스톤 종료 조건이 그것을 요구할 때** — 오늘은 `MILESTONE.md` C2다.
   - **강제 수단이 없다는 것을 여기 적는다.** 상시 게이트 밖이라는 것이 곧 「부르지 않아도 초록」이라는 뜻이고, 이 규율은 사람이 지킨다. 적지 않으면 다음이 이 두 줄을 기계가 재는 것으로 읽는다 — `WEB-UI.md` §2.3이 이름 붙인 *"검사가 실제보다 넓게 주장하는 것"*의 반대 방향 판이다.
   - **재도입 트리거**: 안 불러서 회귀가 실물로 샌 것이 **한 번이라도 관측될 때.** 그때 다시 열리는 것은 이 항이 아니라 **인터뷰 결정 ⑤**(분리 자체)이고, 갈래는 게이트 편입 또는 커밋 훅이다. 그 판정에는 오늘의 실측이 재료로 남아 있다 — 게이트 증분은 시나리오당 1초 아래이고 실제로 값을 치르는 것은 656 MB를 모든 게이트 실행의 전제로 만드는 것이다.

8. **외부 개발 의존성이 하나 는다 — 그 수를 `DISTRIBUTION.md` §8이 들고 계약 테스트가 잰다.** 그 절이 외부 개발 의존성의 종수를 문면으로 들고, 공급망 계약 테스트가 루트의 외부 개발 의존성 **집합**을 정확히 단언한다. 도구를 실제로 들이는 사이클은 **그 둘을 함께 움직여야 한다** — 안 그러면 `pnpm check`가 붉고 원인이 「누가 정했나」로 되돌아온다. 이 절이 그 판정을 여기 적는 이유가 그것이다.
   - **핀은 정확 버전이고 그 대가가 딸려 온다.** 같은 절의 정확 핀과 `minimumReleaseAge`가 합쳐지면 **릴리스 48시간 안의 버전은 핀할 수 없다** — 그 절이 이미 적어 둔 성질이고, 도입 시점에 실제로 걸릴 수 있어 여기서 다시 지목한다.
   - **전이 의존은 이 수에 안 든다.** 계약 테스트가 세는 것은 매니페스트에 선언된 이름이다.

9. **하네스가 화면의 시각 완성도를 재지 않는다.** 스크린샷 비교·시각 회귀를 두지 않는다 — 화면의 정본은 원격 디자인 시스템이고 `MILESTONE.md`가 시각 완성도를 비목표로 이미 들었다. 이 하네스가 재는 것은 **동작**이다.

#### 기각한 갈래

| 갈래 | 기각 근거 |
|---|---|
| `@vitest/browser-playwright`(브라우저 모드) | 재는 대상이 실물에서 재현물로 바뀌고, 도입 근거인 매니페스트 도달 가능성이 그때도 재지는지가 미확인이다. 정적 파일 서버 넷과 WebSocket이 딸려 온다 (결정 1) |
| `@playwright/test` 러너 도입 | 러너가 둘, 단정 문법이 둘이 된다. Vitest가 이미 있다 (결정 1) |
| 가짜 DOM(jsdom 등)으로 대체 | 인터뷰 결정 ②의 기각분. M2가 존재하는 이유 자체를 깬다 — 손으로 만든 가짜를 상대로 재면 재는 것이 그 가짜다 |
| 레포 밖 도구로 1회 검증만 | 인터뷰 결정 ②의 기각분. 재실행 수단이 레포 밖에 남아 「기록만 있고 기계가 없는」 형태가 된다 |
| `pnpm check`에 편입 | 인터뷰 결정 ⑤의 기각분. 656 MB가 모든 게이트 실행의 전제가 되고, 브라우저 자동화 특유의 간헐 실패가 게이트 전체를 붉힌다 |
| 새 워크스페이스 패키지(`packages/e2e`) | 예산 목록·버전 일치 검사·§2.2 예산이 동시에 열린다. 검사 도구 하나에 치를 값이 아니다 (결정 3) |
| `packages/serve/test/`에 둔다 | `serve`가 `cli`를 개발 의존으로 얻어야 하고 그 패키지의 경계 테스트가 형제 엣지를 정확한 수로 단언한다 (결정 3) |
| 파일 이름 규약으로만 게이트와 가른다 | 이름 하나를 잘못 붙이는 날 하네스가 조용히 게이트 안으로 들어오고, 그 실패는 게이트가 느려지는 것으로만 나타난다 (결정 3) |
| 하네스 소스를 타입 검사 밖에 둔다 | 분리가 아니라 무검사다. 실행만 밖이면 정적으로는 낡을 수 없다 (결정 2) |
| 실 API로 도는 e2e | 승인 왕복을 결정적으로 만들 수단이 없고, 키·과금·비결정성이 e2e에 들어온다 (결정 4) |
| 브라우저 부재 시 건너뛴다 | 명시적으로 부른 명령이 브라우저 없이 초록으로 끝난다 — §2.6의 침묵 실패다 (결정 6) |
| 브라우저를 명령이 자동 확보한다 | 656 MB를 처음 부르는 사람이 모르고 받는다 (결정 6) |
| 고정 포트로 붙는다 | `WEB-UI.md` §12의 세부가 하네스의 전제가 되어 계약으로 승격하고, 병렬·재기동이 `EADDRINUSE`를 밟는다 (결정 5) |
| 스크린샷 시각 회귀를 함께 둔다 | 화면의 정본이 원격 디자인 시스템이고 시각 완성도는 마일스톤의 비목표다 (결정 9) |

#### 레퍼런스 대비 — 둘 다 브라우저 e2e를 쓰고, 둘 다 주 게이트 밖에 둔다

**소스는 안 읽었다** — 루트 `docs/hermes-agent-architecture.md`가 답을 이미 들고 있었고 OpenClaw는 매니페스트의 스크립트 표로 충분했다. 상세는 `devnotes/20260828-devnote.md` §2.1이 든다.

| | OpenClaw | hermes-agent |
|---|---|---|
| 도구 | Playwright (개발 의존성) | Playwright (데스크톱 앱) |
| 주 게이트 | e2e를 안 부른다 | e2e를 안 부른다 |
| e2e 자리 | 별도 스크립트가 따로 부른다 | 별도 워크플로 |
| 브라우저 확보 | e2e 스크립트가 매번 앞에서 확보한다 — 설치 전제가 아니다 | 빌드 스텝에 묶인다 |
| 러너 | Vitest + **전용 설정** | `playwright test` |
| 병렬 | 워커 하나로 강제 | — |

**셋이 우리 판정과 겹친다.** ① 주 게이트 밖(결정 2) ② 브라우저를 설치 전제로 안 만든다(결정 6) ③ 워커 강제는 우리가 잰 `EADDRINUSE`와 같은 자리이고, **우리만 겪는 제약이 아니라는 것**이 그 한 줄로 확인된다.

**넷째가 결정 1을 뒷받침한다** — OpenClaw는 Vitest를 러너로 쓰되 브라우저 모드가 아니라 **독립 Playwright + 전용 설정**을 쓴다. 우리가 고른 형태와 같고, 그 배치가 브라우저 모드의 개발 서버와 WebSocket을 안 문다.

**다섯째에서 갈린다 — 브라우저 확보의 처분이 반대다.** 그쪽은 자동 확보이고 우리는 고지 후 실패다(결정 6). 근거가 다르기 때문이다: 그쪽은 기여자가 여럿이라 「전제를 모르는 사람」이 상수이고, 우리는 개인 1인이라 그 사람이 곧 그 비용을 치를 사람이다.

#### 이 절이 재지 못하는 것

- **호출을 강제하는 기계가 없다.** 결정 7이 그 사실과 트리거를 든다. 이 절이 낳는 가장 큰 빚이다.
- **656 MB 발자국을 어느 검사도 안 잰다.** 잠금 파일·pnpm 저장소 밖이라 `DISTRIBUTION.md` §8의 공급망 방어가 이 발자국에는 안 닿는다. 그 절의 정확 핀과 `minimumReleaseAge`가 덮는 것은 npm 패키지 쪽뿐이다.
- **하네스의 자리가 인용 계약과 임포트 예산의 모집단 밖이다.** 결정 3이 그 대가를 든다.
- **하네스가 화면의 시각 완성도를 안 잰다.** 결정 9. 그 자리의 정본은 원격 디자인 시스템이다.
- **모의 모델이 실 와이어와 갈리는 것은 이 하네스가 못 본다.** 그 자리를 재는 것은 라이브 스모크이고, 둘의 모집단이 다르다(결정 4).
