## 2. 확정된 원칙

스택과 무관하게 지킨다. 각 항목은 **되돌리기 어려운 순서**로 배열했다 — 위쪽일수록 나중에 고치기 힘들다.

### 2.1 에이전트 코어는 전송 계층을 모른다

에이전트 루프는 CLI인지 웹인지 메신저인지 알지 못한다. 세션 저장소도, 채널도, 게이트웨이도 모른다. 모델 호출과 도구 실행만 안다.

**왜** — 루프가 채널을 알기 시작하면 되돌릴 수 없다. OpenClaw의 `packages/agent-core/`가 좋은 선례다(의존성 4개, Gateway·세션·채널 전부 비의존). 반대로 hermes는 `run_agent.py` 하나가 7,500줄로 불어난 뒤 `agent/` 하위로 분해하는 중이며, 그 작업이 아직 안 끝났다.

**구체적 규칙**
- 코어는 LLM 호출 구현을 직접 갖지 않는다. 런타임 주입으로 받는다.
- 코어가 반환하는 것은 이벤트 스트림이다. 렌더링·전달은 바깥의 일이다.
- 코어의 의존성 목록은 리뷰 대상이다. 늘어나면 경계가 새고 있다는 신호다.

### 2.2 컴플라이언스는 타입 레벨에서 강제한다

모델 프로바이더 등록 시 인증 경로의 근거를 요구한다. 근거가 공식 문서가 아니면 **작성 자체가 불가능**해야 한다.

**왜** — 두 레퍼런스의 ToS 위반은 한 번에 들어온 게 아니라 "일단 되니까" 하나씩 쌓인 결과다. 코드 리뷰와 문서 규칙으로는 막히지 않는다는 것이 이미 증명됐다. OpenClaw는 근거를 분류하는 코드(`src/agents/provider-attribution.ts`)를 갖고도 **분류만 하고 강제하지 않아서** 위반 경로가 그대로 남았다.

**구체적 규칙 — 금지 대상은 수단이 아니라 오용이다** (2026-09-03 정정)
- 소비자 구독 그랜트를 그 구독이 허용하지 않은 서드파티 클라이언트에서 쓰지 않는다. 엔드포인트도 공식 API 쪽을 쓴다 — 소비자 앱 전용 백엔드로 우회하지 않는다.
- User-Agent·클라이언트 식별자는 정직하게 neo-agent로 보낸다. 다른 제품을 사칭하는 헤더·프롬프트·문자열 치환은 금지.
- 콘텐츠 필터·과금 분류기·레이트리밋·봇 차단을 우회하지 않는다.
- 메시징 채널은 공식 봇 API만. 리버스 엔지니어링 클라이언트는 넣지 않는다.
- **OAuth 자체는 금지 대상이 아니다** — 제공사가 서드파티 도구 사용을 명시적으로 허용한 경로면 합법이고, 그때는 근거 문서 URL을 코드에 남긴다.

**우리 인증 표면은 오늘 공식 API 키 하나다 — 이것은 벤더 경계가 아니라 강제 가능성을 위한 우리 선택이다.** 표면이 둘이면 위의 «작성 자체가 불가능»이 성립하지 않는다: `ProviderRegistration.createClient`의 config가 **인증 자격증명으로 `apiKey` 하나만** 받기 때문에 소비자 그랜트를 실을 자리가 등록 계약에 없다(`CORE-INTERFACE.md` §8).

**두 층 중 어느 것도 단독으로는 총체적이지 않다 — 그것을 여기 적는다.** 타입이 막는 것은 **승인된 경로**다: 등록 계약에 그랜트를 실을 칸이 없으므로 코어를 거쳐 들어올 수 없다. 그러나 어댑터가 `createClient` **안에서** 환경변수나 파일을 직접 읽는 밀반입은 타입이 못 막고, 그 자리를 `packages/providers/test/compliance.test.ts`가 **와이어에서** 잡는다(OAuth Bearer 헤더 부재를 실행으로 잰다). 오늘 `@ts-expect-error`로 컴파일 불가를 재는 것은 정직한 신원(`userAgent`)과 근거 종류(`evidence.kind`) 둘이고 인증 표면은 그 축에 없다 — **타입이 좁힌 것은 계약 표면이고, 표면 밖을 재는 것은 런타임 검사다.** §2.21이 지원 조건에 대해 쓴 자백과 같은 부류이고, 적어 두지 않으면 다음이 이 문단을 「타입 하나로 다 막힌다」로 읽는다. **재도입 트리거** — 제공사가 서드파티 도구용 OAuth를 공식 문서로 허용하고, 그 경로로만 붙는 프로바이더를 실제로 추가할 때. 그 시점에 §8의 `createClient` 표면을 다시 연다.

> **2026-09-03 정정.** 그전까지 이 자리는 *"프로바이더는 공식 API 키 + 공식 엔드포인트**만** 사용한다"* 바로 뒤에 *"OAuth를 쓴다면 …허용한 경로만"*을 이어 적어, 한 목록이 자기 안에서 «OAuth 금지»와 «OAuth 조건부 허용»을 동시에 들었다. 더 큰 문제는 **벤더가 금지하는 것과 우리가 안 하기로 한 것이 안 갈려 있었다는 것**이다 — 「API 키만」은 우리 결정인데 ToS 규칙처럼 읽혔고, 그러면 정직한 벤더 승인 OAuth 경로가 위반으로 오독되는 한편 우리가 표면을 좁힌 진짜 이유(타입 강제)는 문서에서 안 보인다.

상세 금지 목록은 `COMPLIANCE.md`가 든다.

### 2.3 안전한 기본값

설정을 만지지 않은 상태가 가장 안전한 상태여야 한다.

**왜** — 두 레퍼런스 모두 기본값이 안전하지 않다. OpenClaw는 `sandbox.mode: off` + `tools.exec.host: auto`로 설정 없이 쓰면 도구 실행이 호스트에서 그대로 일어나고, hermes는 로컬 백엔드 무격리에 `docker-compose.yml`이 `network_mode: host`다. **나중에 기본값을 조이면 기존 사용자가 깨진다.**

개인용이라 멀티테넌시 경계는 필요 없지만, 그것과 "기본값이 위험해도 된다"는 다른 문제다.

### 2.4 프롬프트 캐시를 깨지 않는다

긴 대화는 매 턴 캐시된 프리픽스를 재사용한다. 과거 컨텍스트를 변경하거나, 대화 중 도구 목록을 바꾸거나, 시스템 프롬프트를 재빌드하면 캐시가 무효화되고 비용이 배가된다.

**예외는 컨텍스트 압축 하나** — 그마저도 과거를 고쳐 쓰는 것이 아니라 세션 분기로 새 프리픽스를 만든다(§2.14, `COMPACTION.md`). 캐시를 버리는 비용은 분기 시점 1회다.

**구체적 규칙** (hermes에서 배운 것)
- 메모리는 세션 시작 시 **프로즌 스냅샷**으로 주입한다. 세션 중 쓰기는 디스크에만 반영하고 프롬프트는 그대로 둔다.
- 프롬프트 상태를 바꾸는 명령(스킬 설치 등)은 기본이 **지연 무효화**(다음 세션부터). 즉시 적용은 명시적 옵트인.
- 스킬 호출은 시스템 프롬프트가 아니라 user 메시지로 주입한다.

### 2.5 코어는 좁게, 기능은 가장자리로

모든 도구 정의는 매 API 호출마다 전송된다. 도구는 늘어나기만 하고 줄지 않으므로, **코어 도구를 추가하는 기준을 극단적으로 높인다.**

새 기능은 아래 사다리에서 **가장 높은 단계**(= 영구 표면이 가장 적은 단계)를 고른다:

1. 기존 코드 확장 (표면 증가 0)
2. CLI 명령 + 스킬 (모델 도구 footprint 0)
3. 조건부 노출 도구 (전제조건 충족 시에만 등장)
4. 플러그인
5. MCP 서버
6. **신규 코어 도구 (최후 수단)** — 근본적이고 거의 모든 사용자에게 유용하며 기존 도구로 도달 불가할 때만

### 2.6 모든 행동은 가시적 결과로 끝난다

사용자나 에이전트의 모든 행동은 **보이는 결과 또는 기록된 의도적 비결과**로 끝나야 한다. 아무것도 만들지 않고 설명도 없는 행동이 가장 나쁜 버그다.

심각도 순서: **silent failure > crash > missing feature.**

### 2.7 기술 스택: TypeScript (2026-08-05 확정)

TypeScript 5.x strict + Node 24 LTS+ + pnpm 워크스페이스 + Zod + `node:sqlite` + 공식 SDK/API 키. 상세 선정과 근거는 **`TECH-STACK.md`**, 결정 경위는 루트 `devlog.md`.

결정을 가른 것은 UI/UX 우선 원칙(한 언어로 CLI→웹→데스크톱)과, 가장 되돌리기 어려운 원칙(§2.1)의 참조 구현(`agent-core`)이 TypeScript라는 점이다. hermes에서 가져올 것들은 정책·알고리즘 수준이라 언어를 건너 재작성해도 잃는 것이 적다.

### 2.8 MVP 범위 (2026-08-05 확정)

1차 릴리스에 포함하는 것:

- **인터페이스: CLI 하나.** 웹·데스크톱은 이후 단계다. 코어가 전송 비의존(§2.1)이므로 인터페이스를 나중에 추가해도 코어는 바뀌지 않는다. UI/UX 우선 원칙은 UI를 만들 때의 품질 기준이지 착수 순서의 강제가 아니다.
- **도구: 파일(읽기·쓰기·편집) + 셸 실행.** 셸이 들어가는 순간 **승인 게이트가 MVP 필수 구성요소**가 된다(§2.3) — 이 구조는 어차피 처음부터 잡아야 하므로 미룰 이유가 없다.
- **세션 영속화: 포함.** `node:sqlite`로 대화 저장·이어가기까지. 전문 검색(FTS5, IDEA-004)은 **미포함** — 도입 시점은 별도 결정(`SESSION-STORE.md` §9).
- **모델 접근: 공식 API 키 1개(Anthropic)로 시작.** 프로바이더 교체 지점은 `ModelClient` 인터페이스로 확정(§2.9).

명시적 제외(1차에 없음): 웹 UI·데스크톱, 메시징 채널, 웹 검색/fetch 도구(SSRF 방어가 범위에 끌려 들어와 첫 릴리스가 커진다), 스킬/플러그인/MCP, 대화 전문 검색.

### 2.9 코어 인터페이스와 프로바이더 교체 지점 (2026-08-05 확정)

에이전트 코어의 공개 계약은 **`CORE-INTERFACE.md`가 정본**이다 — 이벤트 유니온, 큐 상태 머신(prompt/steer/followUp/abort/waitForIdle), 도구 계약(`ToolResult.source` 필수), 훅 2종과 승인 게이트의 자리(코어 밖, `beforeToolCall` 배선).

구 §3.1(프로바이더 추상화)은 여기서 해소됐다: OpenClaw의 Api/Provider 이원화는 채택하지 않고, **`ModelClient` 인터페이스 하나를 교체 지점**으로 좁게 정의한다. 어댑터 등록은 `evidence: { kind: "vendor-documented"; url }` + `userAgent: \`neo-agent/${string}\``를 요구해 §2.2를 컴파일 타임에 강제한다. 이원화 재검토 트리거: 2번째 프로바이더가 실제로 생길 때.

**어댑터 패키지 자신의 경계는 `PROVIDERS.md`가 정본이다** (2026-08-14 신설) — 의존성 예산과 I/O 금지, 크리덴셜 격리(API 키는 파라미터로만), 코어 계약 밖의 구체 표면(모델 컨텍스트 창). 이 절과 `CORE-INTERFACE.md` §8이 계속 드는 것은 **코어가 어댑터에 요구하는 것**이고, 그 문서가 드는 것은 **패키지가 무엇인가**다. 신설 전까지 이 계약들이 네 문서에 이름 없이 흩어져 있었고, 그중 크리덴셜 격리는 어느 문서에도 없이 세 자리가 서로를 인용하는 고리로만 존재했다(`PROVIDERS.md` §4 · 그 상태의 트리는 `31abb2a`).

### 2.10 안전한 기본값의 구체적 값 (2026-08-06 확정)

§2.3의 원칙을 실제 값으로 확정했다. **정본은 `SAFE-DEFAULTS.md`** — 요지:

- **승인 게이트 기본 `"manual"`**: 워크스페이스 안 읽기만 자동 허용, 쓰기·편집·셸·워크스페이스 밖 읽기는 전부 승인. "항상 허용"이 영구 allowlist로 학습. `"off"`로도 하드라인 블록리스트는 우회 불가.
- **샌드박스는 MVP 미포함, 도입 시 기본 on을 지금 약속**: Docker 없으면 셸 도구 비활성화 + 명시적 옵트아웃 안내. 감지 기반 auto 없음. 셸 도구는 실행자(executor) 경계 뒤에 설계(🧬 흔적).
- **시크릿은 전용 파일 + 600 강제(fail-closed) + 자기접근 차단**: 크리덴셜 경로 denylist, 자식 프로세스 env 시크릿 제거, 워크스페이스 `.env` 프로바이더 키 무시. OS 키체인은 후순위(네이티브 의존성 0 원칙과 충돌).
- **보안 설정은 시작 시 1회 읽고 동결** — 실행 중 게이트 약화 경로를 차단.

### 2.11 도구·승인 게이트 인터페이스 (2026-08-06 확정)

MVP 도구 4종(`read_file`/`write_file`/`edit_file`/`shell`)과 승인 게이트의 계약을 확정했다. **정본은 `TOOLS-INTERFACE.md`(도구·워크스페이스 경계·executor)와 `APPROVAL-GATE.md`(게이트 4계층)** — 요지:

- **워크스페이스 경계는 realpath 세그먼트 봉쇄**: `~` 확장 → 실경로 해석(심볼릭 링크는 실체 기준, 미존재 경로는 최근접 조상) → 세그먼트 단위 비교. TOCTOU 미방어를 정직하게 명시(유일한 경계는 OS). 크리덴셜 denylist(`~/.neo-agent/**` 전체 + 워크스페이스 `.env`류)는 게이트가 아니라 **도구 자체가 강제** — 게이트 off에서도 동작.
- **셸은 executor 경계 뒤**(§2.10 🧬의 실체): env 스크러빙·timeout·abort는 executor 계약. 샌드박스 도입 = executor 교체.
- **게이트는 무의존 별도 패키지**(`packages/gate` — fs·child_process·net 임포트 금지를 예산 게이트로 검사): denied → 하드라인 → off → deny 규칙 → 매트릭스 자동 허용 → 위험 패턴 플래그 → allowlist(연산자 숏컷 차단) → 프롬프트. 미등록 도구는 fail-closed(항상 프롬프트). 표시 위조 탐지는 게이트가 소유하고 CLI는 그대로 표시만.
- **edit는 정확 일치만**(유일 일치 요구, fuzzy 기각), 도구는 `ls`/`grep` 없이 4종으로 닫음(셸 경유 + allowlist 학습).

### 2.12 세션 저장소 (2026-08-06 확정)

구 §3.1(상태 저장소)의 해소. **정본은 `SESSION-STORE.md`** — 스키마 v1, 이벤트 구독 계약, 재개 검증 규칙. 요지:

- **DB는 하나다**(`~/.neo-agent/sessions.db`, 테이블 3개 전부 `STRICT`). OpenClaw의 agent/state 2분할은 다중 에이전트·디바이스 페어링·감사의 요구라 개인 1인에 없다. 트리거: 다중 에이전트 프로파일 또는 머신 간 동기화.
- **메시지 본문은 JSON 통짜 저장 + 읽을 때 Zod 검증.** `AgentMessage`가 코어의 닫힌 유니온이므로 정규화하면 계약이 DDL과 타입 두 곳에 존재하게 된다. `role`·`timestamp` 컬럼은 인덱스용 파생이며 파생은 단방향(`body`가 정본).
- **저장은 `message_end`만 구독하고 `INSERT OR IGNORE`로 멱등하다.** 스트리밍 초안은 `stopReason`이 자리표시자라 저장하면 거짓 기록이 된다. 저장소는 CLI 렌더러보다 **먼저** 구독한다 — "사용자가 본 것은 이미 저장된 것".
- **재개 시 워크스페이스 불일치는 거부, 시스템 프롬프트·모델 불일치는 경고 후 진행.** 가르는 기준은 *틀린 결과가 나오는가(엉뚱한 파일 수정), 비싼 결과가 나오는가(캐시 무효화)*.
- **O-4(메시지 id) 해소가 코어 계약을 바꿨다** — `AgentMessage.id` 필수, 발급자는 코어 하나, 와이어로 나가지 않음(캐시 보존). 입력·어댑터 경계는 `Omit` 타입으로 좁힌다(`CORE-INTERFACE.md` §2·§4·§8·불변 조건 8).
- `parent_session_id`는 v1에 nullable로 선반영(🧬 압축용). FTS5는 후순위이며 **흔적조차 불필요**하다 — 원본에서 재구축 가능한 파생 데이터다.

### 2.13 CLI 인터페이스 (2026-08-06 확정)

구 §3.1의 해소. MVP의 마지막 구성요소. **정본은 `CLI-INTERFACE.md`** — 요지:

- **`packages/cli`는 유일한 조립 지점(composition root)이다.** 다른 패키지들이 서로를 모른다는 계약이 전제하는 "호스트의 배선 한 곳"이 여기다. 외부 런타임 의존성 0(`node:readline` + ANSI 직접 제어), 단일 프로세스·데몬 없음(**`neo-agent serve`는 예외로 상주한다 — §2.19.** 좁혀진 것은 상주 금지 하나이고 단일 프로세스는 유지된다). 시작 시퀀스의 순서가 계약이다 — 설정 동결 → 크리덴셜 fail-closed → 경계 생성 → 저장소 → 세션 → Agent → **저장소 구독 먼저, 렌더러 나중**.
- **크리덴셜 로더**: env(`ANTHROPIC_API_KEY`) 우선, 없으면 `~/.neo-agent/credentials`(dotenv형). 파일이 존재하면 사용 여부와 무관하게 600 검사 fail-closed. 로드한 시크릿 값은 executor에 전달돼 자식 프로세스 env에서 스크러빙된다.
- **명령 표면**: argv 5개(`--resume`·`serve` 포함) + 슬래시 명령 중앙 레지스트리(디스패치·`/help`·자동완성 파생). 세션 명령은 목록·재개·삭제(soft-delete — `SESSION-STORE.md` §5에 `deleteSession` 추가됨).
- **렌더링 계약**: 이벤트 스트림만으로 그린다(웹 UI가 같은 자리). 사용자 메시지는 항상 렌더(합성 메시지 누락 방지), `stopReason`·usage는 침묵하지 않는다, 합성 도구 짝은 `message_end`에서 표시. 승인 프롬프트는 게이트의 `display`를 **가공 없이** 표시.
- **화면 층은 셋이고 순서가 계약이다** (2026-08-20 추가 — `CLI-INTERFACE.md` §7.1): 트랜스크립트(append-only) → 상태줄(정확히 1행) → 입력 라인(최하단). 하단 고정 영역은 **한 단위로** 지워지고 그려지며, 갱신은 **이벤트로만** 일어난다(시계를 두지 않는다 — 타이머는 이 절의 폴링 금지를 깬다). 상태줄이 지는 최소 보장은 **안전한 기본값에서 내려온 상태 둘**(승인 `off`·샌드박스 `off`)이고, 그것은 **고지가 아니라 지속**이다 — 고지는 판정이 일어난 자리에서 이미 나간다(`SANDBOX.md` §3의 배너 판정과 같은 근거).
- **입력 상태 머신** 4상태(idle/run/approval/compacting) — 스트리밍 중 Enter가 steer(interrupt-and-redirect), Ctrl+C는 abort.
  > 2026-08-20 정정 — 이 줄은 *"3상태(idle/run/approval)"*였다. `compacting`은 2026-08-06 압축 구현에서 판정 E-44로 **닫힌 목록의 독립 상태**가 됐고(`CLI-INTERFACE.md` §8·`COMPACTION.md` §10), 이 요지만 그때 따라가지 않아 **14일간 거짓이었다.** 요지가 정본의 수를 복제하면 정본이 바뀔 때 함께 늙는다 — `CLI-INTERFACE.md` §1이 두 자리에서 겪고 규율로 세운 것과 같은 형태다.

### 2.14 컨텍스트 압축 (2026-08-06 확정)

- **`compactionSummary` 역할은 불채택 확정** — 모델 비가시 역할이 생기면 의도적으로 제거한 어댑터 변환 계층이 되살아난다(§2.9). 요약 식별은 구조(parent 있는 세션의 첫 메시지)로 한다.

- 저장소는 스키마 v2(messages PK `(session_id, id)`)와 `branchSession`(단일 트랜잭션)이 필요하다 — v1 마이그레이션 체계의 첫 실사용. 2026-08-06 압축 구현 플랜에서 전 패키지 구현 완료 (판정 정본은 압축 QA 리포트).

### 2.16 외부 네트워크 접근과 셸 격리 (2026-08-08 확정)

MVP 이후 세 번째 확장. **정본은 `WEB-ACCESS.md`(웹 도구·SSRF·오염)와 `SANDBOX.md`(셸 격리)** — 두 문서는 **하나의 결정을 나눠 적은 것**이고, 한쪽만 구현하면 설계 의도가 성립하지 않는다.

- **왜 한 묶음인가 — 셸이 이미 `curl`을 칠 수 있다.** 그러므로 `web_fetch`는 §2.5 사다리의 "도달 불가"로 정당화되지 않는다. 정당화는 **감사 가능한 문 하나를 만들고 나머지를 닫는 것**이다: 웹 도구만 넣으면 표면이 순증하고(우회로 존치), 샌드박스만 넣으면 에이전트가 웹을 잃는다. 둘이 같이 와야 표면 순증이 음수가 된다. `REUSE-MAP.md` §3의 세 트리거가 같은 시점을 가리킨 이유다.
- **`web_fetch` 1종만 추가. `web_search`는 트리거로 분리** — SSRF 표면은 전적으로 fetch의 것이고, search는 두 번째 시크릿을 불러와 `SAFE-DEFAULTS.md` §3의 OS 키체인 재검토 트리거를 이 설계로 끌어들인다. Anthropic 서버측 검색 도구는 기각(결과가 승인 게이트·오염 추적·SSRF 판정을 전부 우회한다).

  > **2026-08-31 — 이 분리 판정이 뒤집혔다.** `MILESTONE.md` M3가 그은 트리거(검색 수요 실측)가 발동해 재검토를 거쳤고, `WEB-ACCESS.md` §3.2가 `web_search`를 확정 계약으로 세웠다(구현은 아직 — `WEB-ACCESS.md` §3 머리·`kanban.md` `K-412`). SSRF 표면은 여전히 fetch만의 것이다(§3.2가 그 근거를 새로 든다). 키체인 재검토도 발동해 파일 유지로 닫혔다(`SAFE-DEFAULTS.md` §3). 근거·기각 갈래의 정본은 `WEB-ACCESS.md` §7.
- **SSRF는 IP 피닝 + 홉별 재검증.** 검증된 IP로 연결하되 Host/SNI 보존(DNS 리바인딩 방어), 리다이렉트는 홉마다 판정을 처음부터 재실행. **완화 설정을 만들지 않는다** — 설정 표면이 없으면 약화 경로도 없다. 실측이 수단을 결정했다: 내장 `fetch`(undici)는 dispatcher를 노출하지 않아 피닝 자체가 불가능해 `node:https` 직접 사용이 전제이며, `lookup` 훅이 주소를 배열 전체로 요구하므로 **전원 검증·통과분만 반환**이 계약이다.
- **오염(taint) 정책은 새 계층이 아니라 기존 기계의 재사용** — `source: "network"` 결과가 나온 런에서는 영구 allowlist가 무효화되고 모든 도구가 다시 승인을 받는다(위험 패턴의 "차단이 아니라 숏컷 무효화"와 같은 경로, 사다리 1단). `REUSE-MAP.md` §2.1이 남긴 🧬 흔적의 소비 지점이다.
- **샌드박스는 `SAFE-DEFAULTS.md` §2가 미리 못박은 약속의 이행이다** — 기본 `on`, Docker 없으면 셸 도구를 숨김(실패시키지 않음), `auto` 없음, `network: "none"`·읽기 전용 루트·`cap-drop ALL`·호스트 uid. 대상은 **셸뿐**이고 파일 도구는 호스트에 남는다. `ShellExecutor` 인터페이스는 **한 글자도 바뀌지 않는다**(🧬 흔적의 두 번째 회수).
- **`network: "none"`의 귀결을 감수한다** — 기본 상태에서 셸의 `npm install`·`git push`가 동작하지 않는다. 부작용이 아니라 목적이며, 부수 효과로 `TOOLS-INTERFACE.md` §2의 `source: "local"` 고정이 비로소 사실이 된다.

### 2.17 메모리 — 프로즌 스냅샷 (2026-08-09 확정)

MVP 이후 네 번째 확장. **정본은 `MEMORY.md`.** 이 항목은 트리거 발동이 아니라 **격차 해소**다 — §2.4가 확정 원칙에서 이미 "메모리는 세션 시작 시 프로즌 스냅샷으로 주입한다"를 전제하고 `REUSE-MAP.md` §4도 방향을 판정해 뒀는데 정본 문서와 코드가 없었다.

- **읽기는 이미 공짜다. 문이 필요한 것은 쓰기뿐이다.** 스냅샷이 시스템 프롬프트에 실려 있으므로 모델은 도구 없이 메모리 전체를 보고 있다. 그래서 조회·검색·recall 표면은 **해결할 문제가 없고**, 쓰기 표면은 `remember` **1종·1액션**(`content` 하나, 경로 인자 없음 → traversal 표면 없음)으로 닫는다. 수정·삭제·정리는 전부 사용자(`/memory`, 에디터).
- **저장 위치가 곧 격리다 — 새 기계 0개.** 메모리는 `~/.neo-agent/memory/MEMORY.md`에 있고, 이 경로는 `TOOLS-INTERFACE.md` §3의 크리덴셜 denylist가 **게이트와 무관하게 파일 도구 전부를 차단**하는 영역이다. 따라서 **파일 도구 쪽에서** `remember`가 유일한 문이 되고 그 문이 예산·표시를 강제한다 — `WEB-ACCESS.md` §1이 세운 구조(감사 가능한 문 하나를 만들고 나머지를 닫는다)를 **기존 denylist 재사용으로** 얻었다(§2.5 사다리 1단). 비대칭이 의도다: 사용자는 에디터로 자유롭게 편집하고, 에이전트는 문을 통과한다. 워크스페이스에 두는 대안은 `write_file` 한 번으로 전부 우회되므로 배제 대상이다. **셸은 이 판정을 지나지 않는다** — 격리 소유자가 denylist가 아니라 샌드박스이고(§2.16 · `SANDBOX.md` §6), 기본 구성에서는 `~/.neo-agent/`가 컨테이너 안에 아예 없다. 열려 있는 것은 명시적 `sandbox: "off"` 갈래이며 그때 CLI가 시작 시 경고한다 — 범위의 정본은 `MEMORY.md` §2.1 「한계 — 셸은 이 문을 지나지 않는다」(2026-09-02 확정).
- **압축 분기는 스냅샷을 물려받는다(재읽기 없음).** 구현 변경 0이고(`compact.ts`가 이미 그렇다), "프로즌"이 세션 단위라는 의미가 압축으로 흔들리지 않는다. hermes는 압축에서 프롬프트를 재빌드해 `_cached_prompt_reflects_builtin_memory()`라는 판정기를 짊어졌다 — 우리 구조에는 그 상황이 없다. 귀결: 세션 중 쓴 메모리는 **다음 세션부터** 반영되며, 이는 §2.4의 "지연 무효화 기본"의 예외가 아니라 이행이다.
- **오염된 런에서는 쓰지 못한다(거부).** 승인이 아니라 거부인 이유는 승인 단위(호출 1회)와 효과 범위(이후 모든 세션의 시스템 프롬프트)가 어긋나기 때문이다 — 웹 페이지가 "기억해 두라"고 지시한 순간의 승인 버튼은 사용자가 무엇을 승인했는지 알 수 없는 승인이다. 강제 지점은 게이트가 아니라 **도구 자신**(denylist와 같은 이유로 게이트 `off`에서도 유효).
- **hermes의 메모리 보안 핵심을 안 가져왔다.** 내용 위협 스캔 + `[BLOCKED]` 치환은 `WEB-ACCESS.md` §5가 이미 기각한 방향이다(*"막지 못하는 것을 막는 것처럼 보이는 표시"*). 지속 인젝션의 답은 탐지가 아니라 쓰기 경로를 좁히는 것에서 나온다.
- **예산은 유계이고 초과 시 모델이 아니라 사용자가 정리한다.** hermes는 모델에게 통합을 지시했고 실패 루프가 **턴 예산을 소진해 사용자 답변을 삼킨** 사고를 냈다(#42405) — 그 대응으로 달린 턴당 실패 상한의 존재 자체가 판단 착오의 증거다. FIFO 회전도 채택하지 않는다(사용자가 적은 항목이 예고 없이 사라진다).

### 2.18 배포·설치·실행 (2026-08-09 확정)

MVP 이후 다섯 번째 확장. **정본은 `DISTRIBUTION.md`.** 이 항목도 §2.17과 같이 트리거 발동이 아니라 **격차 해소**다 — `TECH-STACK.md` §8이 *"**배포·번들 형태** — 로컬 실행이 1차라 현재 요구 없음"*(`6d9019e^`)으로 명시적으로 유예했는데, MVP+확장 4건이 완주하고도 **실제 모델을 태운 end-to-end가 0회**이며 그 이유의 절반이 "실행할 방법이 레포 안에만 있다"였다.

- **실측이 형태를 결정했다.** Node는 `node_modules` 아래의 실제 `.ts` 파일에 대해 타입 스트리핑을 **거부**하고(`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`), 심볼릭 링크 경유는 realpath 해석 덕에 **통과**한다. 그러므로 npm publish는 빌드 스텝을 강제하고 링크 설치는 빌드가 0이다. 우리 테스트가 지금 도는 이유도 같다(워크스페이스 링크). **판정: 링크 설치 하나** — clone한 소스 트리가 곧 런타임이고 전역 PATH에는 심볼릭 링크만 놓는다. npm publish의 소비자가 없고(§1), 빌드 없음이 지키는 것(줄번호 일치·드리프트 불가·갱신 절차 없음)이 배포 편의보다 크다. hermes도 wheel/sdist를 의도적으로 차단해 같은 자리에 도달했다.
- **버전 정본은 하나다** — `NEO_AGENT_USER_AGENT`(코드)가 정본, `package.json`의 `version`은 파생이며 예산 게이트가 일치를 강제한다. 역방향이 불가능한 것이 이 판정의 근거다: `providers`는 `node:fs`가 금지된 패키지이고 그 금지의 근거가 `PROVIDERS.md` §2.2(어댑터는 스스로 크리덴셜을 읽지 않는다)이므로, **버전을 읽으려고 파일 읽기를 여는 것은 격리를 versioning 편의와 맞바꾸는 것**이다(2026-08-14 이관 — 그전까지 이 자리는 근거를 §2.2, 즉 컴플라이언스 원칙 절에 귀속시켰으나 그 절은 수령 방식을 들지 않는다. 앵커: `31abb2a`). 사람이 세는 수치가 두 번 어긋났던 전례(devnote 2026-08-09 §9.4)를 버전에서 반복하지 않는다.
- **다운그레이드는 지원하지 않는다.** `migrate.ts`가 상위 버전 DB를 거부하는 것은 `SESSION-STORE.md`의 마이그레이션 규율("앞으로만 간다")이 설계한 동작이고, 배포 관점의 귀결은 **되돌리기의 유일한 수단이 DB 사본**이라는 것이다. 자동 백업은 만들지 않는다(트리거: 데이터를 잃는 마이그레이션이 처음 필요해질 때) — 위험 구간이 "마이그레이션 실패"가 아니라 "성공했는데 물리고 싶을 때"로 좁기 때문이다.
- **설치 트리가 워크스페이스이면 고지하되 막지 않는다.** 크리덴셜·메모리 denylist와 성격이 반대다 — 그쪽은 *에이전트가 접근할 이유가 없는* 영역이고 여기는 *접근하는 것이 목적인* 영역이다(neo-agent로 neo-agent를 개발하는 것이 주 용도). 고지는 realpath 둘의 비교로 **확실히 아는 사실**이라 §2.6의 대상이며, "편집한 코드는 다음 기동부터"까지 말해야 사용자가 왜 안 먹는지 안다. **이 경고는 경계가 아니라 고지다.**
- **TTY 없이 기동하면 거부한다** — `main.ts`에 남아 있던 미규정 R-3의 해소. 승인 게이트가 물어볼 사람이 없는데 묻는 상태의 결말은 조용한 행(hang)이고, §2.6의 심각도 순서에서 **silent failure가 crash보다 나쁘다**는 것이 판정의 전부다. 설치가 되고 나면 의도치 않은 맥락(cron·스크립트)에서 실행될 수 있게 되므로 배포 문서가 닫을 자리다.
- **공급망은 표면이 작을 때 싸게 조인다** — 외부 런타임 의존성 2개 규모에서 정확 핀·`minimumReleaseAge`·`blockExoticSubdeps`·pnpm 고정은 비용이 사실상 0이다. CI는 넣지 않는다(트리거: 외부 기여 PR 또는 게이트 미실행 푸시 사고).

### 2.19 웹 UI — 서버·프로토콜 (2026-08-19 확정)

MVP 이후 여섯 번째 확장. **정본은 `WEB-UI.md`.** §2.8이 1차 릴리스에서 제외한 항목 중 웹 UI를 여는 판정이며, **트리거 발동이다** — `DISTRIBUTION.md` §10이 미결 둘(VPS 상주 · 디자인 시스템 산출물 반입 형태)의 트리거를 웹 UI 착수로 걸어 두었고 이 확장이 그 둘을 함께 소비한다.

- **이 확장의 목적은 §2.1의 검증이다.** 코어가 전송 계층을 모른다는 원칙은 인터페이스가 CLI 하나뿐인 동안 미검증이었다 — 소비자가 하나면 "모른다"와 "하나뿐이라 몰라도 됐다"가 구분되지 않는다. 웹 UI는 그 구분을 만드는 두 번째 소비자이고, `CORE-INTERFACE.md` §3과 `CLI-INTERFACE.md` §7이 그 자리를 미리 예약해 두었다.
- **코어 계약은 한 필드도 늘지 않는다.** 레퍼런스 실독이 규칙을 댔다 — 정규화는 한 자리에 두고 인코딩만 전송별로 분산하며, 웹은 기존 이벤트 계약의 두 번째 구현체일 뿐이다. hermes는 두 번째 프런트엔드를 붙인 **뒤에** 계약을 고치려다 실패했고(정규화 계층이 게이트웨이 안에만 남았다), 우리는 붙이기 **전**이라 그 실패를 피할 수 있다.
- **상주를 도입하되 데몬화하지 않는다.** `CLI-INTERFACE.md` §2의 상주 금지가 **명시적 `serve` 명령일 때만 상주**로 좁혀진다. 단일 프로세스는 그대로이고 포그라운드로 돌며 fork·pidfile을 만들지 않는다 — 수명 관리는 systemd의 일이다. `DISTRIBUTION.md` §2가 배포에서 한 판단과 같다: 남이 이미 하는 일을 우리 표면으로 들이지 않는다.
- **노출은 루프백으로 고정하고 그 값을 설정 항목으로 만들지 않는다.** 원격 접근은 SSH 포트포워딩이며, 그래서 인증·TLS·페어링·레이트리밋 전체가 이 확장의 범위 밖이다 — 경계를 OS가 진다(§2.3의 전제 그대로). **위험한 조합을 검사하는 대신 그 조합을 표현할 수 없게 한 것**이고, 이는 `SANDBOX.md`가 마운트 설정을 안 만들어 검증 대상 자체를 없앤 것과 같은 수단이다.
- **승인은 연결이 아니라 프로세스에 귀속한다.** 승인자가 원격 브라우저가 되면서 처음 생긴 물음이었고(CLI에서는 승인자가 항상 같은 프로세스의 TTY였다), 답은 셋이다 — 코어는 승인을 모른 채 도구 Promise가 늦게 resolve되는 것으로만 대기를 표현하고, 대기 레코드는 연결이 사라져도 남으며, 아무도 답하지 않으면 만료가 **거부**로 settle한다. `AgentEvent`에 승인 이벤트를 더하지 않는다.
- **전송은 SSE + POST이고 WebSocket을 쓰지 않는다** (2026-08-20 확정 · `WEB-UI.md` §2.1). 미결이 *"프레임 파싱을 직접 쓸 것인가 `ws`를 들일 것인가"*라는 **이분법으로 적혀 있었고 그 이분법이 틀렸다** — 셋째 갈래가 둘의 비용을 다 안 낸다. 근거는 프로토콜 자신에 있다: 프레임 셋이 이미 *밀어내는 이벤트*와 *왕복하는 요청*으로 갈려 있어 양방향 소켓이 파는 능력을 쓰지 않는다. **외부 런타임 의존성 0이 이로써 목표가 아니라 계약이 됐다.** 레퍼런스 둘이 같은 방향을 가리켰다 — hermes는 에이전트 스트리밍 전량을 SSE + 개별 POST로 하고 그 위에서 승인의 프로세스 귀속까지 성립시키며, OpenClaw가 `ws`를 쓰는 이유(업그레이드 시점 사전인증·연결 예산·아웃바운드 realtime)는 우리에게 하나도 없다. **되돌릴 수 있다** — 프레임 유니온이 전송을 모르므로 전송 교체는 `packages/serve` 안의 인코더 교체다.
- **종료의 개시자가 CLI와 다르고, 그것이 종료 계약 전체의 골격이다** (2026-08-24 확정 · `WEB-UI.md` §3.2). CLI에서 종료를 시작하는 것은 REPL 입력인데 `serve`에는 REPL이 없다 — **개시자는 프로세스 신호뿐이고 서버를 내리는 메서드를 두지 않는다.** 순서는 CLI 열거를 상속하되 앞에 셋이 붙고(수락 중지 · 종료 고지 · **대기 승인 비우기**), 그중 승인 비우기가 런 대기보다 앞이라는 것이 이 절이 낳은 가장 값진 순서 요구다 — 그러지 않으면 아무도 답할 수 없는 승인을 기다리느라 종료가 만료 시간만큼 지연된다. 레퍼런스 둘이 여기서 갈렸고 hermes 쪽(즉시 거부)을 골랐다. 대기에는 유한한 상한이 걸리고 **그 상한이 이벤트 루프 위에서만 유효하다는 한계를 문서가 스스로 적는다** — 루프 밖 워치독의 수단이 예산 밖이기 때문이며, 그 자리는 systemd가 진다. **같은 사이클이 `serve`의 첫 기동 거부를 반영했고**(§3.1 — `CLI-INTERFACE.md` §2.1이 넘긴 의무), **데몬화 금지에는 명시 단언 대신 금지 목록 확장을 골랐다**(§3.3 — 검사를 만드는 대신 위험한 조합을 표현할 수 없게 하는 수단이고, 같은 문서 §4가 바인드에서 먼저 쓴 것이다).
- **화면 자산의 반입 금지를 좁힌다.** `DISTRIBUTION.md` §10이 2026-08-17에 든 배제 근거 셋 중 둘이 이 확장으로 소멸한다(토큰 소비자 0 · 웹 UI가 §2.8에서 닫힘). 남은 하나(빌드 스텝 없음)는 **빌드 없는 형태만 반입**한다는 제약으로 유지되므로 `TECH-STACK.md` §2는 개정되지 않는다. 손으로 다듬지 않고 재생성 가능성을 계약으로 요구한다 — 정본은 여전히 원격이고 반입물은 파생물이다. **2026-08-26 — 반입할 화면 집합이 확정됐다**(`WEB-UI.md` §9.4). 원격 재고를 처음 실독한 결과가 **부재**였다 — 우리가 원하는 화면은 이름과 문면으로 실재하는데 실물이 React + CDN이라 §9가 못 받고, **같은 프로젝트의 다른 킷이 무빌드 형태의 존재 증명이다.** 그래서 그 자리의 작업은 「반입」이 아니라 **「재생성」**이고, 이 절이 드는 것은 목록이 아니라 규격이다 — 화면 하나 · 평면 · 자기완결 · 모든 참조가 매니페스트 키 · DOM 배선은 이 레포 소유이고 화면이 지는 것은 앵커. **외부 참조는 CSP로 표현 불가능하게 만든다** — 검사하는 대신 조합을 없애는 이 문서의 상습 수단이고, 그 위반이 반입하는 사람의 머신에서는 성공하고 사용자의 오프라인 머신에서만 깨지는 가장 늦은 침묵 실패이기 때문이다.

### 2.20 세계관 헌장 (2026-08-21 확정)

**정본은 `LORE.md`.** `idea.md`의 IDEA-016(채택 2026-08-19)을 정본으로 승격한 것이며, 이 항목은 포인터다.

- **지배 원칙은 «Lore must explain architecture. Architecture must not serve lore.»다.** 세계관은 아키텍처를 이해하기 위한 언어이지 아키텍처가 섬길 대상이 아니다. **§1의 기준 질문 아래에 선다** — 충돌하면 §1이 이긴다.
- **`LORE.md`는 계약 값을 갖지 않는다.** 이름 → 정본 문서의 사전이고, 각 행이 정본 포인터를 의무로 갖는다. 가리킬 곳이 없는 이름은 «정본 없음»으로 표시되며 그 표시가 곧 결함 신고다 — 이 규칙이 세계관을 장식이 아니라 감사 표면으로 만든다.
- **판정은 두 갈래다** (2026-08-21 확정 · `LORE.md` §2.1). 세 물음은 **구조를 더하는 제안**(모듈·추상·계약 표면)에만 걸고, **표면 연출**(문면·연출·한 번의 선택)은 넷으로 판정한다 — 표면에만 사는가 · 지우면 안 깨지는가 · 안전 기본값을 약화시키지 않는가 · 비용 상한을 정본이 드는가. **넷을 통과하면 근거가 «재미»뿐이어도 정당하다.** 지배 원칙이 금지한 것은 «불필요한 **시스템 복잡성**»이지 «불필요한 스텝»이 아니며, 둘을 같게 읽으면 헌장 자신의 파생 원칙(*"재미는 부가기능이 아니라 설계 요소다"*)이 사문이 된다.
- **세계관 이름은 코드 식별자에 반입하지 않는다.** 문서·사용자 대면 문면의 층에서만 쓰고, 패키지·타입·설정 키는 기능 이름을 쓴다(게이트 패키지는 `gate`이지 `smith`가 아니다). 이름이 식별자에 들어가면 그것을 되돌리는 데 개명 커밋이 필요해지고, 그 시점에 아키텍처가 lore를 섬긴다.
- **승격과 함께 대조 부채 하나를 갚았다.** 헌장이 든 Smith 5축을 기확정 계약과 전수 대조했고(`plans/20260821-lore-smith-axes-audit.md`), 다섯이 한 층에 있지 않다는 것과 «Scope» 축에는 대응 계약이 아예 없다는 것이 드러났다. 정정된 읽기는 `LORE.md` §5.1.1이 든다 — **핵심 판정 자체(«Smith는 별도 에이전트가 아니다»)는 대조를 통과했다.**

### 2.21 검증 게이트의 지원 조건과 시간 상한 (2026-08-30 확정)

**정본 문서를 따로 만들지 않는다 — 이 절이 자기완결이다.** 다른 확정 항이 전부 포인터인 것과 다른 이유는 이 판정이 **계약 표면을 하나도 안 늘리기** 때문이다. 정하는 것은 규율 넷이고 실물은 테스트 자리의 주석 하나다. 문서를 새로 세우면 그 문서가 자기 앵커·자기 지위 선언·자기 감사 대상을 함께 달고 오는데, 규율 넷이 치를 값이 아니다.

**자리를 이 문서로 고른 근거.** 후보는 `TECH-STACK.md` §7(개발 도구 체인)이었다 — 지원 조건의 오늘 문면(`pnpm check`·Vitest·전량 런)이 전부 스택의 이름이라 그쪽이 자연스러워 보인다. 그러나 **이 절이 정하는 것은 도구가 아니라 「무엇이 결함인가」의 경계**이고, 그것은 러너를 갈아도 남는다. §2.6이 *가시적 결과*로 그은 선의 반대쪽 끝이기도 하다 — 저쪽이 「침묵하면 안 된다」를 정하고 이 절이 「시끄럽게 붉었다고 다 결함은 아니다」를 정한다. 두 선이 한 문서에 있어야 다음 사람이 둘을 함께 읽는다. `TECH-STACK.md` §7의 표는 도구가 게이트 안인지 밖인지를 들지 그 게이트가 **어떤 조건에서** 뜻이 있는지를 들지 않는다.

**여는 계기** — `K-336`이 2026-08-27에 「고정 ms 상한 축이 부하에서 간헐 red」로 열었고, 2026-08-29 재검증(`plans/20260829-sandbox-web-integration-verify-report.md`)이 **그 자리를 재현 못 하는 대신 다른 파일에서 같은 종을 결정적으로 재현**해 `K-380`으로 확증했다. 판정은 2026-08-30 인터뷰(`plans/20260830-k336-k380-ms-timeout-interview.md`, 상태 `결정됨`)가 닫았고 이 절은 그것을 정본에 착지시킨다.

- **`pnpm check`의 초록은 「전량 런 1본」 아래에서만 뜻이 있다.** 그것이 이 저장소가 지원하는 실행 조건이고, **그 밖에서 붉는 것은 결함이 아니다** — 전량 런을 동시에 두 본 이상 띄우는 것이 오늘 알려진 유일한 지원 밖 조건이다. 이 한 줄이 없으면 「지원 밖 조건에서 붉었다」를 계약 위반과 구별할 근거가 문서 어디에도 없고, 그러면 다음 사람이 같은 조사를 처음부터 다시 한다. **`K-336`이 정확히 그 형태로 세 사이클을 썼다.**
  - **강제 수단이 없다는 것을 여기 적는다.** 이 규율은 사람이 지킨다 — 게이트가 자기 실행 조건을 잴 수는 없다. `TECH-STACK.md` §7.1 결정 7이 e2e 호출에 대해 쓴 자백과 같은 부류이고, 적어 두지 않으면 다음이 이 줄을 기계가 재는 것으로 읽는다.

- **시간 상한은 계약이 아니라 측정 도구다.** 그것이 넘어 붉을 때 붉은 것은 재는 대상이 아니라 **재는 자**다. §2.6의 침묵 실패는 아니다 — 시끄럽게 붉는다. 그러나 **화면에 뜨는 이름이 원인의 이름이 아니다**: `Test timed out in 5000ms`는 계약 위반과 CPU 기아를 같은 문면으로 낸다. 위의 지원 조건 한 줄이 그 이름을 복구하는 유일한 수단이다.

- **부하를 근거로 상한을 올리는 것은 자리 한정이다.** vitest 전역 `testTimeout`도, 공용 대기 헬퍼의 기본값도 올리지 않는다. 자리를 한정하지 않으면 「상한을 올린다」가 **관행**이 되고 그것이 이 판정에서 유일하게 되돌리기 어려운 것이다 — 값 하나를 되돌리는 데는 한 줄이면 되지만 관행을 되돌리는 데는 근거가 필요하다. 2026-08-30 판정이 자리로 든 것은 `packages/providers/test/ub-guard-scope.qa.test.ts`의 「블록 주석 안의 완전 공백 줄은 머리를 안 끊는다」 축 하나이고, 값은 **15000ms**다.

- **부하를 근거로 올린 상한은 그 값 옆에 `측정일 · 측정값 · 배수의 근거` 셋을 문면으로 든다.** 값만 두면 낡는다 — 이 레포는 *"손으로 유지되는 목록은 낡는다"*를 이미 실증했고(2026-08-21 · 루트 `CLAUDE.md`), 근거 없는 매직 넘버는 그 실증의 다음 사례가 된다. 15000의 근거 셋:
  - **(a)** 결정적으로 붉었던 조건이 CPU 여유 1/2~1/3이므로, 측정 최댓값을 덮으려면 최소 3배가 필요하다.
  - **(b)** 그 축은 자리 안 파일 **전량**을 도는 본문이라 레포가 자라면 아무도 안 건드려도 느려진다. 최소값은 오늘만 맞는 숫자이므로 자리가 자랄 여지를 함께 산다.
  - **(c)** 더 올리지 않는 이유는 상한의 본래 일이 「진짜 멈춘 것」을 잡는 것이고, **그 비용은 축 하나가 아니라 전량 런 전체가 낸다.** 대가를 적는다 — 이 자리가 진짜로 멈추는 날 게이트는 5초가 아니라 15초를 기다린다.

- **소급하지 않는다 — 이 각인 요건은 부하를 근거로 올린 상한에만 걸린다.** 이 저장소에는 이미 자리 한정 상한이 여럿 있고(2026-08-30 관측 — Docker 실물·셸 실행·브라우저 기동), **그것들의 근거는 부하가 아니라 「그 작업이 본래 오래 걸린다」**이다. 두 부류를 한 규율로 묶으면 다음 감사가 그 자리 전부를 위반으로 세고, 이 저장소는 「감사가 감사를 낳는」 형태를 이미 한 번 겪었다(`backlog.md` «왜 갈랐나»). **판별은 근거의 종류이지 상한의 존재가 아니다.**

#### 미결 — 이 절이 정하지 않은 것

1. **「고정 ms 상한 기반 축」이라는 묶음이 유효한 판정 단위인가.** 오늘 실측이 보인 것은 형식이 위험을 안 가른다는 것이고 **가르는 것은 여유**인데, 여유는 이 저장소 어디에서도 안 재고 있다. 닫으려면 「축의 여유를 드러내는 수단」이 필요하고 그것은 이번 사정거리(붉은 자리만) 밖이다. **자리 하나를 처분해도 이 물음은 열려 있다.**
2. **species 마커의 재개 조건** — 위 표의 조건부 기각. 오늘의 기각 근거가 「대상이 한 자리뿐」이므로 그 전제가 깨지는 시점이 재개 시점이다.
3. **`K-336` 원 관측의 원인.** 2026-08-27의 발화가 무엇이었는지는 끝내 못 밝혔다. 2026-08-30 실측이 **시간 상한 가설을 배제**했으므로(그 자리의 여유가 압도적이다) 다시 붉으면 그때는 다른 원인(순서 의존·실제 경합)을 본다.

#### 이 절이 재지 못하는 것

- **지원 조건을 재는 기계가 없다.** 게이트가 자기 실행 조건을 잴 수 없다 — 위 첫 항이 그 자백을 든다.
- **축의 여유를 재는 기계가 없다.** 미결 1이 그것이고, 이 절이 낳는 가장 큰 빚이다. 오늘 여유를 아는 유일한 방법은 사람이 한 번씩 재 보는 것이다.
- **상향의 근거 각인을 재는 기계가 없다.** 문면 규율이라 사후 감사의 대상이다. 기계화하지 않는 근거는 머리의 수 서술 금지가 든 것과 같다 — 형태로 오탐을 가를 수 없다.

### 2.22 제품 트리는 자족한다 (2026-09-03 확정)

**정본은 `PUBLIC-TREE.md`.** 이 항목은 포인터다.

- **제품 코드에 걸리는 계약은 제품과 함께 배포된다.** `MARKERS.md` §2가 마커 규약의 자리를 정하며 세운 논증이고, 2026-09-03까지 마커에만 적용돼 있었다 — 컴플라이언스 금지 목록·경계 층 소속·기여 절차가 같은 논증에 걸리는데도 공개 트리 밖에 살았다.
- **판정 단위는 주소의 부류 셋이다** — 공개 · 비공개 기록 · 동결 레퍼런스. **모집단 판별이 문자열 안에서 끝나고**(`DOC-CITATION.md` §3.1이 형식에 대해 세운 기준과 같은 자리) **부류는 해결이 착지한 트리가 정한다** — 접두가 정하는 것은 미해결의 처분뿐이다. 비공개 기록 주소를 금지하지 않는 대신 공개 트리가 그 접두 목록을 고지하고, 그 대가로 그 주소는 작업 폴더에서 실제로 풀려야 한다.
- **경계 층 소속은 기계가 낸다.** 손으로 유지되는 것은 층의 선언이고 파일 목록은 생성물이며, 드리프트가 게이트를 붉힌다. 2026-08-21에 문서 쪽에서 난 위반을 구현↔문서 대조가 원리적으로 못 잡은 자리(`LORE.md` §6의 주석)가 이 수단이 겨냥하는 사고다.
- **세계관 이름은 생성 산출물에 안 들어간다.** 생성물의 이름은 생성기 소스의 리터럴에 살고 그것은 코드다 — `LORE.md` §6의 반입 금지가 그대로 걸린다. 그 §6 표 자체를 넓히는 일은 이 판정이 하지 않는다.
- **수용 시험은 게이트가 아니다.** 맥락 없는 에이전트가 공개 트리만 받아 과제를 끝내는지를 1회로 재고, 그 결과를 회귀 신호로 쓰지 않는다.
