## 2. 확정된 원칙

스택과 무관하게 지킨다. 각 항목은 **되돌리기 어려운 순서**로 배열했다 — 위쪽일수록 나중에 고치기 힘들다.

### 2.1 에이전트 코어는 전송 계층을 모른다

에이전트 루프는 CLI인지 웹인지 메신저인지 알지 못한다. 세션 저장소도, 채널도, 게이트웨이도 모른다. 모델 호출과 도구 실행만 안다.

**왜** — 루프가 채널을 알기 시작하면 되돌릴 수 없다. OpenClaw의 `packages/agent-core/`가 좋은 선례다(의존성 4개, Gateway·세션·채널 전부 비의존). 반대로 hermes는 `run_agent.py` 하나가 7,500줄로 불어난 뒤 `agent/` 하위로 분해하는 중이며, 그 작업이 아직 안 끝났다.

**구체적 규칙**
- 코어는 LLM 호출 구현을 직접 갖지 않는다. 런타임 주입으로 받는다.
- 코어가 반환하는 것은 이벤트 스트림이다. 렌더링·전달은 바깥의 일이다.
- 코어의 의존성 목록은 리뷰 대상이다. 늘어나면 경계가 새고 있다는 신호다.

### 2.2 컴플라이언스는 타입 레벨에서 강제한다

모델 프로바이더 등록 시 인증 경로의 근거를 요구한다. 근거가 공식 문서가 아니면 **작성 자체가 불가능**해야 한다.

**왜** — 두 레퍼런스의 ToS 위반은 한 번에 들어온 게 아니라 "일단 되니까" 하나씩 쌓인 결과다. 코드 리뷰와 문서 규칙으로는 막히지 않는다는 것이 이미 증명됐다. OpenClaw는 근거를 분류하는 코드(`src/agents/provider-attribution.ts`)를 갖고도 **분류만 하고 강제하지 않아서** 위반 경로가 그대로 남았다.

**구체적 규칙**
- 프로바이더는 공식 API 키 + 공식 엔드포인트만 사용한다.
- OAuth를 쓴다면 해당 제공사가 서드파티 도구 사용을 **명시적으로 허용한 경로**만, 근거 문서 URL을 코드에 남긴다.
- User-Agent·클라이언트 식별자는 정직하게 neo-agent로 보낸다. 다른 제품을 사칭하는 헤더·프롬프트·문자열 치환은 금지.
- 메시징 채널은 공식 봇 API만. 리버스 엔지니어링 클라이언트는 넣지 않는다.

상세 금지 목록은 루트 `CLAUDE.md`의 "컴플라이언스 — 이식 금지 목록".

### 2.3 안전한 기본값

설정을 만지지 않은 상태가 가장 안전한 상태여야 한다.

**왜** — 두 레퍼런스 모두 기본값이 안전하지 않다. OpenClaw는 `sandbox.mode: off` + `tools.exec.host: auto`로 설정 없이 쓰면 도구 실행이 호스트에서 그대로 일어나고, hermes는 로컬 백엔드 무격리에 `docker-compose.yml`이 `network_mode: host`다. **나중에 기본값을 조이면 기존 사용자가 깨진다.**

개인용이라 멀티테넌시 경계는 필요 없지만, 그것과 "기본값이 위험해도 된다"는 다른 문제다.

### 2.4 프롬프트 캐시를 깨지 않는다

긴 대화는 매 턴 캐시된 프리픽스를 재사용한다. 과거 컨텍스트를 변경하거나, 대화 중 도구 목록을 바꾸거나, 시스템 프롬프트를 재빌드하면 캐시가 무효화되고 비용이 배가된다.

**예외는 컨텍스트 압축 하나.**

**구체적 규칙** (hermes에서 배운 것)
- 메모리는 세션 시작 시 **프로즌 스냅샷**으로 주입한다. 세션 중 쓰기는 디스크에만 반영하고 프롬프트는 그대로 둔다.
- 프롬프트 상태를 바꾸는 명령(스킬 설치 등)은 기본이 **지연 무효화**(다음 세션부터). 즉시 적용은 명시적 옵트인.
- 스킬 호출은 시스템 프롬프트가 아니라 user 메시지로 주입한다.

### 2.5 코어는 좁게, 기능은 가장자리로

모든 도구 정의는 매 API 호출마다 전송된다. 도구는 늘어나기만 하고 줄지 않으므로, **코어 도구를 추가하는 기준을 극단적으로 높인다.**

새 기능은 아래 사다리에서 **가장 높은 단계**(= 영구 표면이 가장 적은 단계)를 고른다:

1. 기존 코드 확장 (표면 증가 0)
2. CLI 명령 + 스킬 (모델 도구 footprint 0)
3. 조건부 노출 도구 (전제조건 충족 시에만 등장)
4. 플러그인
5. MCP 서버
6. **신규 코어 도구 (최후 수단)** — 근본적이고 거의 모든 사용자에게 유용하며 기존 도구로 도달 불가할 때만

### 2.6 모든 행동은 가시적 결과로 끝난다

사용자나 에이전트의 모든 행동은 **보이는 결과 또는 기록된 의도적 비결과**로 끝나야 한다. 아무것도 만들지 않고 설명도 없는 행동이 가장 나쁜 버그다.

심각도 순서: **silent failure > crash > missing feature.**

### 2.7 기술 스택: TypeScript (2026-08-05 확정)

TypeScript 5.x strict + Node 24 LTS+ + pnpm 워크스페이스 + Zod + `node:sqlite` + 공식 SDK/API 키. 상세 선정과 근거는 **`TECH-STACK.md`**, 결정 경위는 루트 `devlog.md`.

결정을 가른 것은 UI/UX 우선 원칙(한 언어로 CLI→웹→데스크톱)과, 가장 되돌리기 어려운 원칙(§2.1)의 참조 구현(`agent-core`)이 TypeScript라는 점이다. hermes에서 가져올 것들은 정책·알고리즘 수준이라 언어를 건너 재작성해도 잃는 것이 적다.

### 2.8 MVP 범위 (2026-08-05 확정)

1차 릴리스에 포함하는 것:

- **인터페이스: CLI 하나.** 웹·데스크톱은 이후 단계다. 코어가 전송 비의존(§2.1)이므로 인터페이스를 나중에 추가해도 코어는 바뀌지 않는다. UI/UX 우선 원칙은 UI를 만들 때의 품질 기준이지 착수 순서의 강제가 아니다.
- **도구: 파일(읽기·쓰기·편집) + 셸 실행.** 셸이 들어가는 순간 **승인 게이트가 MVP 필수 구성요소**가 된다(§2.3) — 이 구조는 어차피 처음부터 잡아야 하므로 미룰 이유가 없다.
- **세션 영속화: 포함.** `node:sqlite`로 대화 저장·이어가기까지. 전문 검색(FTS5, IDEA-004)은 **미포함** — 도입 시점은 별도 결정(`SESSION-STORE.md` §9).
- **모델 접근: 공식 API 키 1개(Anthropic)로 시작.** 프로바이더 교체 지점은 `ModelClient` 인터페이스로 확정(§2.9).

명시적 제외(1차에 없음): 웹 UI·데스크톱, 메시징 채널, 웹 검색/fetch 도구(SSRF 방어가 범위에 끌려 들어와 첫 릴리스가 커진다), 스킬/플러그인/MCP, 대화 전문 검색.

### 2.9 코어 인터페이스와 프로바이더 교체 지점 (2026-08-05 확정)

에이전트 코어의 공개 계약은 **`CORE-INTERFACE.md`가 정본**이다 — 이벤트 유니온, 큐 상태 머신(prompt/steer/followUp/abort/waitForIdle), 도구 계약(`ToolResult.source` 필수), 훅 2종과 승인 게이트의 자리(코어 밖, `beforeToolCall` 배선).

구 §3.1(프로바이더 추상화)은 여기서 해소됐다: OpenClaw의 Api/Provider 이원화는 채택하지 않고, **`ModelClient` 인터페이스 하나를 교체 지점**으로 좁게 정의한다. 어댑터 등록은 `evidence: { kind: "vendor-documented"; url }` + `userAgent: \`neo-agent/${string}\``를 요구해 §2.2를 컴파일 타임에 강제한다. 이원화 재검토 트리거: 2번째 프로바이더가 실제로 생길 때.

### 2.10 안전한 기본값의 구체적 값 (2026-08-06 확정)

§2.3의 원칙을 실제 값으로 확정했다. **정본은 `SAFE-DEFAULTS.md`** — 요지:

- **승인 게이트 기본 `"manual"`**: 워크스페이스 안 읽기만 자동 허용, 쓰기·편집·셸·워크스페이스 밖 읽기는 전부 승인. "항상 허용"이 영구 allowlist로 학습. `"off"`로도 하드라인 블록리스트는 우회 불가.
- **샌드박스는 MVP 미포함, 도입 시 기본 on을 지금 약속**: Docker 없으면 셸 도구 비활성화 + 명시적 옵트아웃 안내. 감지 기반 auto 없음. 셸 도구는 실행자(executor) 경계 뒤에 설계(🧬 흔적).
- **시크릿은 전용 파일 + 600 강제(fail-closed) + 자기접근 차단**: 크리덴셜 경로 denylist, 자식 프로세스 env 시크릿 제거, 워크스페이스 `.env` 프로바이더 키 무시. OS 키체인은 후순위(네이티브 의존성 0 원칙과 충돌).
- **보안 설정은 시작 시 1회 읽고 동결** — 실행 중 게이트 약화 경로를 차단.

### 2.11 도구·승인 게이트 인터페이스 (2026-08-06 확정)

MVP 도구 4종(`read_file`/`write_file`/`edit_file`/`shell`)과 승인 게이트의 계약을 확정했다. **정본은 `TOOLS-INTERFACE.md`(도구·워크스페이스 경계·executor)와 `APPROVAL-GATE.md`(게이트 4계층)** — 요지:

- **워크스페이스 경계는 realpath 세그먼트 봉쇄**: `~` 확장 → 실경로 해석(심볼릭 링크는 실체 기준, 미존재 경로는 최근접 조상) → 세그먼트 단위 비교. TOCTOU 미방어를 정직하게 명시(유일한 경계는 OS). 크리덴셜 denylist(`~/.neo-agent/**` 전체 + 워크스페이스 `.env`류)는 게이트가 아니라 **도구 자체가 강제** — 게이트 off에서도 동작.
- **셸은 executor 경계 뒤**(§2.10 🧬의 실체): env 스크러빙·timeout·abort는 executor 계약. 샌드박스 도입 = executor 교체.
- **게이트는 무의존 별도 패키지**(`packages/gate` — fs·child_process·net 임포트 금지를 예산 게이트로 검사): denied → 하드라인 → off → deny 규칙 → 매트릭스 자동 허용 → 위험 패턴 플래그 → allowlist(연산자 숏컷 차단) → 프롬프트. 미등록 도구는 fail-closed(항상 프롬프트). 표시 위조 탐지는 게이트가 소유하고 CLI는 그대로 표시만.
- **edit는 정확 일치만**(유일 일치 요구, fuzzy 기각), 도구는 `ls`/`grep` 없이 4종으로 닫음(셸 경유 + allowlist 학습).

### 2.12 세션 저장소 (2026-08-06 확정)

구 §3.1(상태 저장소)의 해소. **정본은 `SESSION-STORE.md`** — 스키마 v1, 이벤트 구독 계약, 재개 검증 규칙. 요지:

- **DB는 하나다**(`~/.neo-agent/sessions.db`, 테이블 3개 전부 `STRICT`). OpenClaw의 agent/state 2분할은 다중 에이전트·디바이스 페어링·감사의 요구라 개인 1인에 없다. 트리거: 다중 에이전트 프로파일 또는 머신 간 동기화.
- **메시지 본문은 JSON 통짜 저장 + 읽을 때 Zod 검증.** `AgentMessage`가 코어의 닫힌 유니온이므로 정규화하면 계약이 DDL과 타입 두 곳에 존재하게 된다. `role`·`timestamp` 컬럼은 인덱스용 파생이며 파생은 단방향(`body`가 정본).
- **저장은 `message_end`만 구독하고 `INSERT OR IGNORE`로 멱등하다.** 스트리밍 초안은 `stopReason`이 자리표시자라 저장하면 거짓 기록이 된다. 저장소는 CLI 렌더러보다 **먼저** 구독한다 — "사용자가 본 것은 이미 저장된 것".
- **재개 시 워크스페이스 불일치는 거부, 시스템 프롬프트·모델 불일치는 경고 후 진행.** 가르는 기준은 *틀린 결과가 나오는가(엉뚱한 파일 수정), 비싼 결과가 나오는가(캐시 무효화)*.
- **O-4(메시지 id) 해소가 코어 계약을 바꿨다** — `AgentMessage.id` 필수, 발급자는 코어 하나, 와이어로 나가지 않음(캐시 보존). 입력·어댑터 경계는 `Omit` 타입으로 좁힌다(`CORE-INTERFACE.md` §2·§4·§8·불변 조건 8).
- `parent_session_id`는 v1에 nullable로 선반영(🧬 압축용). FTS5는 후순위이며 **흔적조차 불필요**하다 — 원본에서 재구축 가능한 파생 데이터다.

### 2.13 CLI 인터페이스 (2026-08-06 확정)

구 §3.1의 해소. MVP의 마지막 구성요소. **정본은 `CLI-INTERFACE.md`** — 요지:

- **`packages/cli`는 유일한 조립 지점(composition root)이다.** 다른 패키지들이 서로를 모른다는 계약이 전제하는 "호스트의 배선 한 곳"이 여기다. 외부 런타임 의존성 0(`node:readline` + ANSI 직접 제어), 단일 프로세스·데몬 없음. 시작 시퀀스의 순서가 계약이다 — 설정 동결 → 크리덴셜 fail-closed → 경계 생성 → 저장소 → 세션 → Agent → **저장소 구독 먼저, 렌더러 나중**.
- **크리덴셜 로더**: env(`ANTHROPIC_API_KEY`) 우선, 없으면 `~/.neo-agent/credentials`(dotenv형). 파일이 존재하면 사용 여부와 무관하게 600 검사 fail-closed. 로드한 시크릿 값은 executor에 전달돼 자식 프로세스 env에서 스크러빙된다.
- **명령 표면**: argv 4개(`--resume` 포함) + 슬래시 명령 중앙 레지스트리(디스패치·`/help`·자동완성 파생). 세션 명령은 목록·재개·삭제(soft-delete — `SESSION-STORE.md` §5에 `deleteSession` 추가됨).
- **렌더링 계약**: 이벤트 스트림만으로 그린다(웹 UI가 같은 자리). 사용자 메시지는 항상 렌더(합성 메시지 누락 방지), `stopReason`·usage는 침묵하지 않는다, 합성 도구 짝은 `message_end`에서 표시. 승인 프롬프트는 게이트의 `display`를 **가공 없이** 표시.
- **입력 상태 머신** 3상태(idle/run/approval) — 스트리밍 중 Enter가 steer(interrupt-and-redirect), Ctrl+C는 abort.

## 3. 미결 항목

**결정 없이 코드를 쓰기 시작하면 안 되는 것들.** 결정되면 이 절에서 §2로 옮기고 `devlog.md`에 근거를 남긴다.

**2026-08-06 기준 비어 있다** — MVP 구성요소 전부의 설계가 §2로 확정됐다(구 §3.1 CLI가 마지막, §2.13). 각 정본 문서의 "미결" 절에 남은 것은 구현 시 확정할 세부(트렁케이션 수치, 패턴 목록, 기본 모델 문자열 등)이지 설계 미결이 아니다. 새 미결이 생기면 여기 등록한다.
