# 문서 지위 선언 규약

**`neo-agent-main/docs/*.md` 머리가 무엇을 선언해야 하는가의 정본.**

- 상태: 구현 완료
- 근거: scripts/check-doc-status.mjs
- 작성일: 2026-08-13

> **이 문서는 자기 자신의 첫 시험 사례였고, 그 시험이 실제로 발동했다.** 이 줄은 2026-08-13에 `구현 전`으로 작성됐다 — 그때는 `근거:`가 가리키는 게이트 스크립트가 없었기 때문이다. 스크립트를 작성한 직후 게이트를 처음 돌리자 **이 문서가 `anchor-present`(§4 ⑦)로 잡혔다.** 다른 문서들이 전부 `missing`(①)이던 첫 실행에서 유일하게 다른 위반이었고, 그것이 예고한 대로 이 줄을 `구현 완료`로 바꾸게 했다. 설계가 말한 *"구현이 착지하는 순간 게이트가 깨진다"*가 이 문서에서 먼저 일어났다.

**불변(계약)**: 머리 필드의 이름과 값 유니온(§3), 게이트가 판정하는 일곱 가지 실패(§4), 파서가 관대해지지 않는다는 것(§3.3).
**조정 가능(세부)**: 실패 메시지 문구, 탐색 줄 수 상한, 스크립트의 파일 위치.

이 문서는 `plans/20260813-docs-headers-verify-report.md` U-1(미규정)의 해소이자, `ARCHITECTURE.md`:7이 *"이 금지를 검사하는 수단이 없었고 지금도 없다"*고 자백한 자리에 수단을 놓는 첫 조각이다.

전제는 `SAFE-DEFAULTS.md` 머리와 같다: **여기 있는 어떤 것도 보안 경계가 아니다.** 이 게이트는 문서가 조용히 거짓이 되는 것을 막는 장치이고, 그 이상을 주장하지 않는다.

## 1. 경계 — 이 규약이 다루는 것과 다루지 않는 것

| 다룬다 | 다루지 않는다 |
|---|---|
| `neo-agent-main/docs/*.md`의 **머리 지위 선언** | 본문 각 절이 코드와 일치하는가 (`K-002` — §8 U-b) |
| 선언된 상태 ↔ **실물 경로의 존재/부재** | 실물의 *내용*이 문서와 맞는가 |
| 선언 형식의 기계적 강제 | `최종 개정:` 이력, 참조 목록, 문체 |
| 루트 `docs/`(레퍼런스 분석) 밖 — **우리 설계 문서만** | `packages/*/test/`·`.claude/`·`plans/`의 머리 |

**예외 목록을 두지 않는다.** `neo-agent-main/docs/` 안의 `.md`는 전부 대상이다. 예외를 허용하면 예외 목록 자체가 다음 부패 후보가 되고, 이 레포는 이미 그 실패를 겪었다 — `SANDBOX.md`:5의 손으로 유지된 6개 문서 목록이 그것이다. 그 목록은 정확했지만, 정확했다는 것이 **사람이 한 번 더 세어 확인해야만** 알 수 있었다.

## 2. 왜 필드여야 하는가 — 세 부패가 각각 다른 것을 요구했다

2026-08-13의 전수 대조가 세 유형을 한 사이클에 냈다(`plans/20260813-docs-headers-verify-report.md`). 원인이 다르므로 처방도 달라야 하고, 아래 설계는 셋을 각각 다른 수단으로 막는다.

| 부패 | 실물 | 이 규약이 막는 방식 |
|---|---|---|
| **F-1** — 6개 문서가 `구현 전`인데 패키지가 존재 (7일·4일) | 안 건드려서 낡음 | **게이트가 매 `pnpm check`마다 대조한다.** `구현 전` + 앵커 존재 = 위반(§4 ⑦) |
| **F-2** — `구현 완료(검색 제외)`가 구현 5일 뒤 개정에도 생존 | 건드렸는데도 낡음 | **괄호 한정을 표현할 수 없게 만든다.** 값은 닫힌 유니온이고 파서는 정확 일치만 받는다(§3.3) |
| **F-3** — 수 서술 금지가 같은 파일 안에서 두 번 깨짐 | 금지가 있는데도 발생 | **금지의 예외를 명문화한다**(§6). 검사 수단 없는 규칙은 규칙이 아니라 의도의 기록이다 |

### 2.1 F-2가 가장 무겁고, 검사로는 못 잡는다

F-1은 검사가 잡는다. F-3은 예외를 명문화하면 판정이 끝난다. **F-2만 다르다** — `구현 완료(검색 제외)`는 그 자체로 참인 문장이었고, 검색이 구현되면서 조용히 거짓이 됐다. 어떤 대조 규칙을 세워도 괄호 안의 자연어를 실물과 맞출 수는 없다.

그래서 이 설계는 F-2를 **검사하지 않고 표현 불가능하게 만든다.** 값이 세 개뿐인 닫힌 유니온에는 "단 X는 예외"를 적을 자리가 없다. 한정이 필요하면 본문에 쓰고, 머리는 전체에 대해 참인 한 값만 든다.

이것이 `ARCHITECTURE.md` §2.2(컴플라이언스를 타입 레벨에서 강제)와 설계 원칙 4(**불가능한 상태는 타입으로 배제**)를 문서 형식에 적용한 것이다.

### 2.2 필드 파서는 자기오염에 걸리지 않는다 — 이것이 grep 격자와 갈리는 지점

이 레포는 **자기오염을 세 번 겪었다**(2026-08-12 수 서술 격자 · 08-13 crontab 주석 · 08-13 문서 머리 감사). 구조는 매번 같다 — 정정 주석이 옛 문면을 되살리고, 그 문자열을 찾는 grep이 설명 텍스트에 걸린다. `devnotes/20260813-devnote.md` §11의 처방은 *"검사는 파일이 아니라 **주장이 사는 절 범위**에 걸어야 한다"*였다.

**필드는 그 처방의 가장 강한 형태다 — 주장이 사는 범위가 한 줄로 축소된다.** 정정 주석이 옛 상태를 아무리 인용해도 파서는 `- 상태:` 로 시작하는 비인용 줄만 읽는다(§3.3). 부재를 찾는 grep과 달리, 필드 파서는 **무엇을 읽을지 자신이 정한다.**

이것이 10사이클의 *"격자를 하나 더 만들지 않는다"* 판정과 충돌하지 않는 이유이기도 하다. 그 판정이 거부한 것은 **문자열 패턴을 하나 더 늘리는 것**이고, 이 설계는 패턴을 늘리지 않는다 — 문서가 스스로 신고하는 필드를 하나 만들고 그것만 읽는다.

## 3. 계약 — 머리 필드

### 3.1 타입

파일에 적히는 형태는 한국어 필드다. 아래는 파서가 만드는 값이다.

```typescript
/** `neo-agent-main/` 기준 상대 경로. 파일 또는 디렉터리 하나. */
type AnchorPath = string;

/**
 * 문서 머리가 선언하는 지위. 닫힌 유니온이며, 값에 한정·괄호·마크업을 붙일 수 없다.
 * `근거:` 줄의 존재 여부가 kind에 의해 완전히 결정된다 — 옵셔널이 아니다.
 */
type DocStatus =
  /** `- 상태: 구현 완료` + `- 근거: <경로>` — 앵커가 존재해야 한다 */
  | { readonly kind: "implemented"; readonly anchor: AnchorPath }
  /** `- 상태: 구현 전`   + `- 근거: <경로>` — 앵커가 부재해야 한다 */
  | { readonly kind: "not-yet"; readonly anchor: AnchorPath }
  /** `- 상태: 구현 주장 없음` — `근거:` 줄을 두면 위반 */
  | { readonly kind: "no-claim" };

type Violation =
  | "missing"          // ① `상태:` 줄이 없다
  | "duplicate"        // ② `상태:` 줄이 둘 이상이다
  | "unknown-value"    // ③ 유니온 밖의 값 (여기서 F-2의 괄호 한정이 잡힌다)
  | "anchor-required"  // ④ implemented|not-yet 인데 `근거:` 가 없다
  | "anchor-forbidden" // ⑤ no-claim 인데 `근거:` 가 있다
  | "anchor-missing"   // ⑥ implemented 인데 앵커 경로가 없다
  | "anchor-present";  // ⑦ not-yet 인데 앵커 경로가 있다  ← F-1 6건이 여기

/**
 * 판정의 산출. 성공 갈래는 `status`를 **통째로** 든다 — `kind` + 옵셔널 `anchor`로
 * 평탄화하면 `{kind:"no-claim", anchor:"x"}`가 타입상 합법이 되어 위 불변("`근거:`의
 * 유무가 kind에 의해 완전히 결정된다")이 판정 경계에서 풀린다.
 *
 * **문서 이름은 이 타입에 없다.** 판정 함수는 소스 텍스트와 앵커 존재 여부만 받으므로
 * 파일명을 원리적으로 만들 수 없다 — 게이트 루프가 파일명과 짝지어 출력한다.
 * (2026-08-13 명문화: 최초 문면은 두 갈래 모두에 `doc: string`을 뒀는데, 그것은 순수
 * 판정에서 만들 수 없는 값이었다. QA 독립 검증이 잡았다.)
 */
type Verdict =
  | { readonly ok: true; readonly status: DocStatus }
  | { readonly ok: false; readonly violation: Violation; readonly detail: string };
```

### 3.2 세 값이 무엇을 뜻하는가

| 값 | 뜻 | `근거:` |
|---|---|---|
| `구현 완료` | 이 문서의 계약이 실물로 존재한다 | **필수** — 존재해야 하는 경로 |
| `구현 전` | 계약은 확정됐고 실물은 아직 없다 | **필수** — *아직 없어야 하는* 경로 |
| `구현 주장 없음` | 이 문서는 구현 상태를 주장하지 않는다 | **금지** |

`구현 전`이 앵커를 드는 것이 이 설계의 핵심이다. **앵커 없는 `구현 전`은 검사할 수 없고, 검사할 수 없는 선언이 정확히 F-1이 7일간 산 방식이다.** 구현이 착지하는 순간 게이트가 ⑦로 깨지므로, 머리를 고치는 것이 구현 커밋의 일부가 된다 — 나중에 기억해서 하는 일이 아니게 된다.

`구현 주장 없음`은 도피처가 아니다. 이 값을 고른 문서는 **본문 어디에서도 구현 상태를 주장하지 않아야** 하며, 주장하면 그것은 이 규약이 아니라 `K-002`(본문 격자)의 대상이다. 2026-08-13 대조에서 `MEMORY`·`REUSE-MAP`·`SEARCH`·`SESSION-STORE`가 적합 판정을 받은 근거가 *"주장이 없으면 거짓일 수 없다"*였다 — 그 상태를 값으로 승격한 것이다.

### 3.3 파서는 관대하지 않다

| 규칙 | 근거 |
|---|---|
| 탐색 범위는 파일 **첫 40줄** | 머리는 머리에 있다. 본문 인용까지 읽으면 자기오염이 되살아난다 |
| 줄이 `- 상태: ` 로 **정확히** 시작 — 선행 공백·`>` 인용·들여쓰기 불가 | 정정 주석은 `>` 블록이므로 자동 배제된다(§2.2) |
| 값은 순수 텍스트 **정확 일치**. `**구현 완료**` 는 위반 | 관대한 파서는 `구현 완료(검색 제외)`도 통과시킨다. 그것이 F-2다 |
| `상태:`·`근거:` 는 **각각 자기 줄**을 갖는다 | §3.4 |
| `상태:` 줄은 파일당 **정확히 1개** | 0개(미선언)와 2개 이상(모호)을 각각 다른 위반으로 잡는다 |

### 3.4 필드를 한 줄에 몰지 않는 이유 — F-2의 진짜 원인

`CLI-INTERFACE.md`:3은 개정 이력 8건을 나열한 뒤 마지막에 `상태:`를 붙인 한 줄이었다. **`(검색 제외)`가 5일간 살아남은 것은 그 괄호가 그 줄의 끝에 있었기 때문이다** — 같은 줄의 다른 부분을 고치면서 눈이 거기까지 가지 않았다.

그래서 각 필드는 자기 줄을 갖는다. 이것은 미관이 아니라 **F-2의 인과에 직접 대응하는 수정**이다.

`최종 개정:` 이력은 이 규약이 규정하지 않는다(§8 U-c). 다만 `상태:`·`근거:` 와 같은 줄에 둘 수 없다.

### 3.5 `설계 확정`을 필드에서 뺀다

개정 전 문서 머리는 `상태: 설계 확정, **구현 완료**` 형태로 두 축을 한 줄에 들었다(`945fe4f`에서 필드로 교체). **`설계 확정`은 필드에서 뺀다.**

근거 둘. 첫째, 기계가 대조할 실물이 없다 — 무엇과 맞춰 볼 것인가. 이 규약의 원칙은 **선언은 기계가 검사할 수 있을 때만 의무**다. 둘째, `neo-agent-main/docs/`의 문서가 **예외 없이 전부** `설계 확정`이라 변별력이 0이다. 설계 중인 것은 애초에 여기 있지 않다 — 위치가 이미 그 사실을 말한다.

## 4. 게이트 — 무엇을 검사하는가

- 자리: **`neo-agent-main/scripts/check-doc-status.mjs`**(2026-08-13 신설). `pnpm check`가 부른다.
- **판정과 실행부는 파일이 다르다.** 순수 판정(§3·§3.3)은 부작용 없는 `scripts/doc-status.mjs`에 살고, 위 파일은 순회·앵커 확인·출력만 맡는다. 한 파일이면 계약 테스트가 판정 함수를 임포트하는 것만으로 게이트 전체가 돌고, 실물이 레드인 날엔 `process.exit(1)`이 테스트 워커를 죽여 **"계약 위반"이 "테스트 파일이 사라짐"으로 나타난다**(2026-08-13 QA 발견 · 선례는 `package-boundary.contract.test.ts`가 예산 게이트를 임포트 대신 텍스트로 읽는 것). `import.meta.main` 가드는 쓰지 않는다 — 그 속성은 Node 24.2.0에서 들어왔고 `engines`는 `>=24`라 24.0~24.1에서 게이트 본문이 통째로 건너뛰어진다. **침묵 통과는 이 게이트가 존재하는 이유 그 자체이므로** 런타임 조건 대신 파일 경계로 가른다.
- 예산 게이트(`check-core-budget.mjs`)에 합치지 **않는다** — 그쪽의 검사 대상은 `packages/` 안이고 이것은 `docs/`다. 실패 메시지가 섞이면 "무엇이 깨졌나"가 흐려진다.
- 판정은 §3.1의 7가지. **판정되지 않은 문서는 통과가 아니다** — 예산 게이트가 이미 쓰는 방식(`EXPECTED_CONSISTENCY_NOTES` 대조)을 그대로 따라, 발견한 `.md` 수와 판정한 수가 다르면 그 자체로 실패다.
- 출력은 `docs/` 파일 수만큼의 행. 성공도 조용하지 않다 — `ARCHITECTURE.md` §2.6(모든 행동은 가시적 결과로 끝난다).

**게이트가 잡지 못하는 것을 여기 적어 둔다.** 앵커가 존재한다는 것은 `구현 완료`의 필요조건이지 충분조건이 아니다. 빈 디렉터리도 존재하고, 계약과 무관한 파일도 존재한다. 이 게이트는 **7일간 거짓인 머리**를 잡지 **한 시간 전에 거짓이 된 머리**를 잡지 않는다. 그것을 잡으려면 본문 절 단위 앵커가 필요하고 그것이 `K-002`다.

## 5. 문서별 확정 값

**아래 표가 이 절의 정본이고, 문서의 수는 여기서 세지 않는다**(`ARCHITECTURE.md`:7과 같은 근거 — 손으로 센 수는 문서가 하나 늘면 어긋난다). 표에 없는 `.md`가 `neo-agent-main/docs/`에 있으면 그것은 표의 누락이며 §4 게이트가 ①(미선언)로 잡는다.

## 6. `ARCHITECTURE.md`:7 수 서술 금지의 예외 명문화

**판정(2026-08-13, 유저): 과거 시점 관측은 금지 밖이다. 다만 예외를 문구에 명문화한다.**

`ARCHITECTURE.md`:7의 금지를 집행하며 단 정정 주석이 `1284`·`1,944`·`2,099`를 들고 있어 자기 저촉 여부가 열려 있었다. 판정 근거: 그 수치는 **날짜와 근거 리포트 경로가 함께 박힌 과거 관측**이므로 실물이 변해도 거짓이 되지 않는다. 금지가 겨냥한 것은 *"지금 몇인가"*를 주장하는 수이지 *"그때 몇이었나"*를 기록하는 수가 아니다.

미규정으로 두고 이 판단만 내리면 **다음 감사가 같은 것을 또 판정한다.** 그래서 금지 문구 자체를 개정한다:

> **예외 — 과거 시점 관측.** 날짜와 근거(리포트 경로 또는 커밋)가 함께 박힌 정정 주석의 수치는 이 금지 밖이다. 판별 기준은 **시제**다 — 날짜 없이 현재를 주장하는 수는 예외가 아니다.

예외가 새는 자리가 되지 않도록 판별 기준을 함께 못박았다. `K-025` 사이클의 교훈(*"조건을 하나 더 두면 그 조건이 다음에 새는 자리가 된다"*)이 여기 걸리는데, 그 사이클이 조건 추가를 기각한 이유는 **비용이 0이었기 때문**이다(no-op push가 exit 0). 여기는 다르다 — 예외를 안 두면 정정 주석에서 근거 수치를 전부 빼야 하고, 그러면 *"이 줄은 N일간 거짓이었다"*가 얼마나 어긋났는지를 말할 수 없게 된다. 즉 대안의 비용이 실재한다.

**이 예외는 §4 게이트의 검사 대상이 아니다.** 수 서술 금지의 기계화는 이 문서가 열어 두는 항목이다(§8 U-d).

## 8. 미결 — 이 문서가 정하지 않은 것

- **U-a. `providers`에 정본 문서가 없다.** 10개 패키지 중 유일하게 대응 문서가 없고, 계약이 `CORE-INTERFACE` §8 + `SAFE-DEFAULTS` §3 + `ARCHITECTURE` §2.2에 흩어져 있다(`devnotes/20260813-devnote.md` §12.1). 이 규약은 문서→실물 방향만 검사하므로 **문서 없는 패키지는 원리적으로 못 잡는다.** 역방향 검사를 걸 것인지가 별도 판정이다.
- **U-b. 본문 절 단위 앵커** — `K-002`(문서 본문이 코드보다 낡음)의 남은 범위. 이번 설계로 K-002의 범위가 *"머리는 이제 게이트가 본다 — 남은 것은 본문"*으로 좁혀졌다.
- **U-c. `최종 개정:` 이력의 형식·길이 상한.** `CLI-INTERFACE.md`:3의 이력이 8건까지 자랐고 그 길이가 F-2의 원인 중 하나였다(§3.4). 다만 잘라내는 규칙은 정보 손실을 낳으므로 지금 정하지 않는다.
- **U-d. 수 서술 금지의 기계화.** §6이 예외를 명문화했을 뿐 검사 수단은 여전히 없다. `ARCHITECTURE.md`:7의 자백(*"새 수치가 들어오면 다음 사후 감사까지 조용히 산다"*)이 그대로 유효하다.
- **U-e. `packages/*/test/`·`scripts/`·`plans/` 머리**는 이 규약 밖이다(§1). `test/` 머리는 `K-006`이 들고 있다.
