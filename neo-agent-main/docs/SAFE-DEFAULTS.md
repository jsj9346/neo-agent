## 1. 승인 게이트 기본 정책

### 모드는 2개로 닫는다

```typescript
/** 닫힌 유니온 — "smart"는 후순위(REUSE-MAP §2.2), 소비자가 생길 때 추가한다 */
type ApprovalMode = "manual" | "off";
```

- **기본값: `"manual"`.**
- `"off"`는 명시적 옵트인이며, **하드라인 블록리스트(게이트 1계층)는 `"off"`에서도 동작한다** — hermes와 동일. 하드라인은 의도적으로 최소(루트 FS 파괴급)로 유지한다. 넓히면 "어차피 다 막네"가 되어 옵트인의 의미가 사라진다.
- 모드는 **프로세스 시작 시 1회 읽고 동결**한다(임포트 시점 동결 원칙, REUSE-MAP §2.2). 세션 중 env·설정 변경으로 게이트가 풀리는 권한상승 경로를 차단한다.

### `"manual"`의 기본 정책 매트릭스

| 도구 행동 | 기본 동작 | 근거 |
|---|---|---|
| 파일 읽기 — 워크스페이스 안 | **자동 허용** | 읽기 승인은 마찰 대비 이득이 없다. 전부 물으면 사용자가 게이트를 끈다(게이트의 자멸) |
| 파일 읽기 — 워크스페이스 밖 | 승인 | 홈 디렉터리의 크리덴셜·개인 파일이 대상이 될 수 있다 |
| 파일 쓰기·편집 | 승인 | 조용한 덮어쓰기는 §2.3("안 만진 상태가 가장 안전")과 정면 충돌 |
| 셸 실행 | 승인 | MVP에서 가장 위험한 표면. 샌드박스 부재(§2)의 균형추 |
| 크리덴셜 경로 (§3 denylist) | **차단 — 승인으로도 불가** | 게이트 4계층 밖의 별도 차단. "실수로 허용"이 존재하지 않게 |
| `web_fetch` — 최초 호스트 (2026-08-08 추가) | 승인 | URL 자체가 유출 경로다(`https://attacker/?d=…`는 GET 하나로 데이터를 내보낸다). 학습 단위는 `스킴+호스트+포트` — 정본은 `WEB-ACCESS.md` §6 |

- 승인 프롬프트의 "항상 허용" 응답은 **영구 allowlist**(게이트 4계층)에 학습된다 — 마찰은 사용 시간에 비례해 감소한다. 복합 명령의 셸 연산자 숏컷 차단(hermes `_has_allowlist_shell_operator` 대응물)을 포함한다.
- 거부는 `beforeToolCall`의 `{ decision: "block", reason }`으로 모델에게 보인다(CORE-INTERFACE §7) — 침묵 거부 없음(§2.6).
- **워크스페이스 경계의 정확한 정의**(기준 디렉터리, 심볼릭 링크·`..` 처리)는 `TOOLS-INTERFACE.md` §3으로 확정됐다(2026-08-06 — realpath 세그먼트 봉쇄, denylist는 도구 자체 강제).

## 2. 샌드박스 — MVP 미포함, 도입 시 기본 on

**MVP에는 샌드박스가 없다.** MVP의 방어는 §1의 승인 게이트(셸 전량 승인)다. Docker를 필수 의존성으로 만들면 "설치 즉시 동작"이 깨지고, 컨테이너 수명주기·마운트 정책·이미지 관리가 첫 릴리스로 끌려 들어온다.

대신 **도입 시점의 기본값을 지금 약속으로 못박는다** — 나중에 기본값을 조이는 문제(§2.3의 "기존 사용자가 깨진다")를 회피하는 방법은 조이는 시점을 미리 계약해 두는 것뿐이다:

1. **샌드박스가 도입되는 릴리스부터 기본값은 `on`이다.** `off`가 기본인 채로 출시되는 일은 없다(레퍼런스가 비판받는 바로 그 상태).
2. `on`인데 Docker가 없으면 **셸 도구를 조건부 노출 원칙("사용 불가 도구는 실패시키지 말고 숨긴다", REUSE-MAP §2.3)에 따라 비활성화**하고, 사용자에게 두 갈래를 명시한다: Docker 설치 또는 명시적 `sandbox: "off"` 옵트아웃(호스트 실행 선택). 감지 기반 자동 전환(auto)은 없다 — 같은 설정이 머신마다 다른 보안 수준이 되는 것은 §2.6(가시적 결과) 위반이다.
3. 도입 시 Docker 하드닝 기본값은 OpenClaw의 것을 기준선으로 재작성한다: `network: "none"`, `readOnlyRoot: true`, `capDrop: ["ALL"]`, no-new-privileges + `validate-sandbox-security.ts`의 denylist(Docker 소켓 전 별칭, `.ssh`/`.aws`/`.gnupg` 등 홈 민감 경로).

**지금 남기는 흔적(🧬)**: 셸 도구는 실행 백엔드를 직접 품지 않고 **실행자(executor) 경계 뒤에서 호출하도록 설계한다** — 샌드박스 도입이 셸 도구 재작성이 아니라 실행자 교체가 되도록. 2026-08-06 `TOOLS-INTERFACE.md` §4(`ShellExecutor` 계약)로 실체화됐다.

도입 트리거: **웹 fetch/search 도구 도입 시 함께**(외부 유래 콘텐츠가 셸로 흐르기 시작하는 시점 — taint 추적 `source: "network"`가 실제로 발생하는 최초 지점), 또는 그 전이라도 allowlist가 커져 게이트의 실질 방어력이 약해졌다고 판단될 때.

> **2026-08-08 — 트리거 발동, 약속 이행됨.** `web_fetch` 도입과 함께 샌드박스를 채택했다. **정본은 `SANDBOX.md`**(이 절은 약속의 기록으로 남는다). 위 약속 3개는 **완화 없이** 이행됐다 — 기본 `on`, `auto` 없음, 하드닝 기준선 그대로. 두 가지만 이 절의 서술과 달라졌으니 함께 적는다: (1) OpenClaw denylist는 **채택하지 않았다** — 마운트 추가 설정을 만들지 않아 검증 대상 자체가 없다(재도입 트리거는 `SANDBOX.md` §7), (2) 🧬 흔적은 예상대로 회수됐다 — `ShellExecutor` 인터페이스 무변경, `HostShellExecutor` → `DockerShellExecutor` 교체만.

## 3. 시크릿 저장 — 전용 파일 + 600 강제 + 자기접근 차단

MVP의 시크릿은 Anthropic API 키 1개다. **OS 키체인은 쓰지 않는다** — 크로스플랫폼 키체인 라이브러리(keytar류)는 네이티브 의존성 0 원칙(TECH-STACK)과 충돌하고, `security` CLI 방식은 macOS 전용 코드가 된다. 대신 평문 파일이되 레퍼런스가 하지 않는 보호를 계약으로 강제한다:

```
~/.neo-agent/credentials     ← 시크릿 전용 파일. 파일 포맷은 구현 시 확정
~/.neo-agent/config.*        ← 동작 설정. 시크릿을 두지 않는다 (hermes 규율, REUSE-MAP §2.7)
```

### 보호 계약 4개

1. **권한 600 강제, fail-closed** — 기동 시 credentials 파일 권한을 검사하고, 600(소유자 외 접근 가능)이 아니면 **명시적 에러로 기동을 거부**한다(수정 명령 안내 포함). 자동 chmod로 조용히 고치지 않는다 — 노출돼 있었다는 사실 자체가 사용자에게 보여야 한다(§2.6).
2. **에이전트 자기접근 차단** — 파일·셸 도구에 크리덴셜 경로 denylist(`~/.neo-agent/credentials`, 워크스페이스 `.env` 등)를 적용한다. §1 매트릭스의 "승인으로도 불가" 행이다. 단 이것은 실수 방지이지 격리가 아니다(문서 머리의 전제).
3. **자식 프로세스 env에서 시크릿 제거** — 셸 도구가 스폰하는 프로세스의 환경 변수에서 API 키류를 기본 제거한다(hermes `env_passthrough` 개념의 재작성). 에이전트가 실행한 스크립트가 `printenv`로 키를 읽는 경로를 차단한다.
4. **워크스페이스 `.env`의 프로바이더 키 무시, fail-closed** — 클론된 저장소의 `.env`에 든 `ANTHROPIC_API_KEY`류를 읽지 않는다(OpenClaw 양성 사례의 재작성). 악성 저장소가 트래픽을 자기 엔드포인트로 돌리는 경로를 차단한다.

키체인 재검토 트리거: 시크릿 종류가 2개 이상이 되거나(봇 토큰 등), 멀티머신 동기화 요구가 실재할 때.

> **2026-08-31 — 트리거 발동, 재검토 수행, 판정은 「파일 유지」다.** `web_search` 도구 도입으로 시크릿이 2종(Anthropic API 키 + 검색 API 키)이 되어 **첫째 조건이 실제로 성립했다**(`WEB-ACCESS.md` §3.2, `MILESTONE.md` M3 C1). 미루지 않고 재검토를 돌렸으며 결론은 **지금 방식 유지**다.
>
> 근거 셋:
> 1. 크로스플랫폼 키체인 라이브러리(keytar류)는 **네이티브 의존성 0 원칙과 충돌한다** — 이 프로젝트가 `node:sqlite` 선택에서까지 지킨 원칙이고, 이 절의 원 판정이 든 근거와 같다.
> 2. **주 머신이 헤드리스 리눅스 VPS다**(`CLAUDE.md` 레포 운영 절, 2026-08-08 확정). macOS Keychain은 실사용 환경에 존재하지 않고, 리눅스에는 표준 금고가 없어 데스크톱 환경마다 갈린다. `security` CLI 방식은 그때도 macOS 전용 코드였고 지금은 **아무 환경도 안 맞는** 코드가 된다.
> 3. **시크릿이 2개가 됐다고 파일 하나의 보호 계약이 약해지지 않는다.** 위 보호 계약 4개는 전부 파일·경로·값 단위이지 종류 수의 함수가 아니다 — 실제로 셋은 구조적으로 이미 이행된다(`WEB-ACCESS.md` §3.2가 항목별로 짚는다).
>
> **첫째 조건은 이 판정으로 소진된다.** 셋째·넷째 시크릿이 생겨도 이 재검토를 다시 열지 않는다 — 위 근거 셋 중 어느 것도 종류 수에 의존하지 않으므로, 종류가 는다는 사실만으로는 결론이 바뀔 수 없다. **남는 조건은 「멀티머신 동기화 요구가 실재할 때」 하나이며, 그것이 이 트리거의 유일한 재개 조건이다.** 이 소진을 문면으로 적지 않으면 시크릿이 늘 때마다 같은 재검토가 반복된다.
>
> 이 판정에 물려 있는 것 하나: 검색 프로바이더 후보 중 SearXNG를 기각한 둘째 근거가 *"시크릿 0의 이점이 값을 잃었다"*이다(`WEB-ACCESS.md` §7). **이 판정이 뒤집히면 그 기각도 다시 열린다.**

## 4. 보안 설정의 공통 규율 — 시작 시 동결

§1의 모드 동결을 일반화한다(REUSE-MAP §2.7 "설정 스냅샷 원칙"): **보안에 영향을 주는 모든 설정(승인 모드, denylist, 샌드박스 방침)은 프로세스 시작 시 1회 읽고 동결한다.** 프로세스 안에서 도는 어떤 코드도(도구 실행, 프롬프트 인젝션 산출물 포함) 실행 중 게이트를 약화시킬 수 없다. 설정 변경의 적용 시점은 다음 프로세스 시작이다 — 이는 프롬프트 캐시 보존(§2.4)의 지연 무효화 기본과도 결이 같다.

## 5. 레퍼런스 대비 의도적 축소

| 레퍼런스 기능 | 판정 | 근거·트리거 |
|---|---|---|

| 승인 모드 3종(`manual/smart/off`) | 2종으로 축소 | smart 후순위의 귀결. `ApprovalMode` 유니온 확장은 싼 변경 |
| 샌드박스 백엔드 4종(docker/podman/ssh/openshell) | 도입 시 docker 1종부터 | 개인 1머신. podman은 도입 시점에 재검토 |
| 샌드박스 모드 3종(`off/non-main/all`) + 스코프 3종 | 도입 시 on/off 2값 | `non-main`은 멀티 에이전트 개념. 우리는 에이전트 1개 |
| SecretRef sentinel 간접 참조 | 안 넣음 | 시크릿 1개에 간접 계층은 과설계. 시크릿 소비 지점이 어댑터 1곳뿐 |
