## 1. 이 문서가 푸는 문제

`ARCHITECTURE.md` §1의 질문("이게 개인 유저 1명에게 필요한가")이 여기서는 반대 방향으로 작동한다. 배포는 보통 "여러 사람에게 전달하는 일"이라 개인용에서는 대부분 불필요한데, **실행 가능한 상태로 만드는 일**만은 사용자가 1명이어도 필요하다. 그 최소선이 무엇인지를 정한다.

현재 상태의 실측:

| 확인 | 값 |
|---|---|
| `package.json` | `private: true`, 빌드 스크립트 없음 |
| `packages/cli` `bin` | `neo-agent` → `./src/main.ts` — **이후 §3.2의 shim(`./bin/neo-agent.mjs`)으로 교체됨** |
| 실행 가능 범위 | pnpm 워크스페이스 **안에서만** |
| 공개 레포 `README.md` | *"스캐폴딩 전. 기술 스택이 정해지지 않아 `src/` 구조를 만들지 않았다"* — 10패키지를 푸시한 상태에서 **사실 오류** |
| 버전 문자열 | `registration.ts:18` 하드코딩 + `package.json` `version` — **두 곳, 동기화 강제 없음** |
| CI | 없음 |

## 2. 배포 형태 — 링크 설치 하나 (2026-08-09 확정)

**clone한 소스 트리를 그대로 런타임으로 쓰고, 전역 PATH에는 심볼릭 링크만 놓는다. 빌드 산출물을 만들지 않고 npm에 배포하지 않는다.**

### 2.1 이 판정을 가른 실측

Node의 네이티브 타입 스트리핑(`TECH-STACK.md` §2 — 빌드 스텝을 두지 않는 근거)에는 문서에 없던 제약이 있다. 2026-08-09 이 머신(Node v25.9.0)에서 측정했다:

| 배치 | 결과 |
|---|---|
| `node_modules/` 아래의 **실제 `.ts` 파일** import | **거부** — `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` |
| `node_modules/` 아래의 **심볼릭 링크**가 바깥 `.ts`를 가리킴 | **통과** (Node가 realpath로 해석 → 실제 경로가 `node_modules` 밖) |
| 전역 PATH의 bin 심볼릭 링크 → `packages/cli/src/main.ts` | **동작** — 레포 밖(`/tmp`)에서 `neo-agent --version` → `0.1.0`, `--help` 정상 (이 측정은 §7의 TTY 거부가 생기기 **전**이다. 지금은 **TTY에서만** 그렇고 비-TTY에서는 `--version`도 거부된다 — 재현하려면 `script -qec "neo-agent --version" /dev/null`) |

(구현 후 재측정 — 링크 대상은 §3.2의 shim(`packages/cli/bin/neo-agent.mjs`)으로 바뀌었고 결과는 같다. 심볼릭 링크 경유 실행은 **shim의 실행 비트에 의존**하므로 그 파일은 git에 `100755`로 기록된다.)

**이 세 줄이 배포 형태를 결정한다.** npm publish는 tarball을 전개해 실제 파일을 `node_modules`에 놓으므로 **빌드 스텝을 강제한다**. 링크 설치는 realpath가 소스 트리를 가리키므로 빌드가 0이다. 우리 테스트가 지금 도는 이유도 같다 — pnpm 워크스페이스의 `node_modules/@neo-agent/*`가 전부 심볼릭 링크다(실측 확인).

### 2.2 왜 링크 설치인가

**1. npm publish의 소비자가 없다.** `ARCHITECTURE.md` §1이 대상을 "개인 사용자 1명"으로 못박았고, 배포 대상은 본인 머신들(현재 VPS 1대)이다. 공개 레포가 있다는 것과 패키지를 배포한다는 것은 다른 문제다 — 전자는 코드를 읽을 수 있게 하는 것이고, 후자는 **설치 계약을 지는 것**이다.

**2. 빌드 스텝 없음이 지키는 것이 크다.** 소스가 곧 실행물이므로 ① 스택 트레이스의 줄번호가 실제 소스와 일치하고 ② 산출물/소스 드리프트가 구조적으로 불가능하며 ③ `git pull` 외의 갱신 절차가 없다. 빌드를 넣으면 셋 다 잃는다. TECH-STACK §2가 이 셋을 얻으려고 고른 것을 배포 편의로 되돌리지 않는다.

**3. hermes가 같은 판정을 했다.** wheel/sdist 빌드를 `setup.py` 오버라이드로 **의도적으로 차단**하고 배포 경로를 셸 인스톨러/Docker/Nix로 한정했다(`docs/hermes-agent-architecture.md` §2.3). 동기는 다르지만(그쪽은 관리형 체크아웃 강제) 결론이 같다는 것은 이 형태가 실전에서 성립한다는 방증이다.

**재도입 트리거** — 제3자 설치 요구가 **실제로** 생길 때(공개 레포에 설치 문의 이슈가 열리는 등). 그때 npm 경로는 **순수 추가**다: 링크 설치를 없애지 않고 배포 산출물만 별도로 만들면 된다. 지금 미리 만들면 두 종류의 실행물이 생기는데 검증되는 곳은 하나뿐이라, **배포본에서만 깨지는 경로**가 열린다.

### 2.3 배제한 대안

| 대안 | 판정 | 근거 |
|---|---|---|
| npm publish (빌드 도입) | ❌ | 위 §2.2. 트리거: 제3자 설치 요구 실증 |
| 셸 인스톨러 (`curl \| bash` — hermes) | ❌ | 제3자 배포용 편의이고, 신뢰 요구가 clone보다 크다. 소비자가 본인 하나면 `git clone` 한 줄이 더 정직하다 |
| 관리형 체크아웃 강제 (`$HERMES_HOME/...` — hermes) | ❌ | 설치 위치를 강제하는 것은 지원 부담을 줄이려는 요구다. 지원 대상이 본인뿐이면 위치는 자유여도 된다 |
| Docker 이미지 배포 | ❌ | 셸 도구가 이미 Docker를 쓴다(`SANDBOX.md`). 중첩 컨테이너는 그 설계를 복잡하게만 한다. 트리거: VPS 상주(§10 미결) |
| Nix (hermes `flake.nix` + 18모듈) | ❌ | 재현 가능한 환경의 가치는 인정하나 유지 비용이 개인 1인 규모를 넘는다 |

## 3. 실행 전제와 버전 게이트

### 3.1 설치 절차 (README가 담을 것)

```bash
git clone <repo> && cd neo-agent/neo-agent-main   # 워크스페이스는 저장소 루트의 하위다
pnpm install                                      # 워크스페이스 심볼릭 링크 생성
mkdir -p ~/.local/bin
ln -s "$PWD/packages/cli/bin/neo-agent.mjs" ~/.local/bin/neo-agent
```

`neo-agent` 명령 이름은 `CLI-INTERFACE.md` §1의 기확정 계약이고 여기서 바꾸지 않는다. 계약은 "**전역 PATH에 놓이는 것은 심볼릭 링크이고 실체는 소스 트리에 있다**"이며, 수단은 **세부**다.

**수단은 직접 `ln -s`로 고정한다** (2026-08-09 T-006 실측). `pnpm link --global`을 쓰지 않는 근거는 둘이고, 첫째가 계약 위반이다:

| 수단 | 실측 | 판정 |
|---|---|---|
| `ln -s <repo>/packages/cli/bin/neo-agent.mjs ~/.local/bin/neo-agent` | 문자 그대로 심볼릭 링크. `readlink -f`가 소스 트리에 닿는다 | ✅ 채택 |
| `pnpm link --global` | PATH에 놓이는 것이 **854바이트 셸 래퍼**(`exec node <path>`)다. `readlink -f`가 **자기 자신**을 반환한다. 게다가 이 머신에서는 `PNPM_HOME` 미설정이라 `pnpm setup`이 선행돼야 하고 **그것이 `~/.bashrc`를 편집한다** | ❌ |

래퍼도 결국 소스 트리를 실행하므로 §2.1의 *결론*은 살아남지만, 그것은 `exec` 인자를 통해서지 realpath를 통해서가 아니다 — **결론이 우연히 성립하는 것과 계약 문장이 참인 것은 다르다.** 플랜 R-3이 이 경우를 미리 판정해 뒀다: 수단 변경은 계약 변경이 아니다.

### 3.2 bin 진입점은 버전 게이트를 통과한 뒤에만 `.ts`를 로드한다

**문제**: 타입 스트리핑이 없는 Node에서 `main.ts`를 실행하면 `ERR_UNKNOWN_FILE_EXTENSION`류의 암호 같은 실패로 죽는다. `CLI-INTERFACE.md` §2가 요구하는 *"원인과 다음 행동을 담은 에러로 종료"*가 아니다. `package.json`의 `engines`는 `pnpm install` 시점에만 보이므로 실행 시점을 지키지 못한다.

**닭과 달걀**: 버전을 검사하는 코드가 `.ts`면 그 코드부터 실행되지 않는다.

**계약**:

- bin은 `packages/cli/bin/neo-agent.mjs`(순수 JS)를 가리킨다. 이 파일이 하는 일은 **둘뿐**이다: ① `process.versions.node`의 major가 최소선 미만이면 원인·현재 버전·요구 버전·다음 행동을 담은 메시지를 stderr에 쓰고 비정상 종료 ② 통과하면 `../src/main.ts`를 동적 import.
- **shim은 그 외 어떤 것도 import하지 않는다.** 예산 게이트가 이 파일을 검사 범위에 포함한다.
- 이는 `main.ts`가 이미 지키는 규율("정적 import 없음 — 경고 필터가 `node:sqlite`보다 먼저 설치돼야 한다")의 연장이다. 진입점에서 순서가 중요한 일을 하고 나머지를 동적으로 부르는 형태가 하나 더 늘어난 것이지, 새 패턴이 아니다.
- **`main.ts`는 여전히 조립에 넘길 `process.*`를 읽는 유일한 곳이다.** shim도 `process.versions`·`stderr`·`exit`를 만지지만 그 값을 **조립에 흘려보내지 않는다** — 자기 실행 가부의 조건일 뿐이다. 계약의 실체는 "`process`를 건드리는 파일이 하나"가 아니라 "**주입되는 값의 출처가 하나**"이므로 shim은 그 계약의 예외가 아니다(2026-08-09 QA-A가 문면의 부정확을 지적해 조인 문장).
- **major를 읽지 못하면(`NaN`) 통과가 아니라 거부다.** §3.2 문면이 정한 것은 "최소선 미만이면 거부"까지이고 판정 불능은 `ARCHITECTURE.md` §2.6에서 도출한 fail-closed다 — 통과시키면 그 다음에 나오는 것이 정확히 이 파일이 대체하려던 암호 같은 실패다. **계약의 강화이지 변경이 아니다.**

**최소 Node 버전은 `TECH-STACK.md` §2가 정한 24다.** shim의 상수와 `engines` 필드는 같은 값이어야 하며, 일치 검사는 §4와 같은 자리(예산 게이트)에서 한다.

## 4. 버전 정본은 하나다

**`NEO_AGENT_USER_AGENT`(`packages/providers/src/anthropic/registration.ts`)가 버전의 정본이고, `package.json`의 `version`은 파생이다.**

**왜 코드가 정본인가** — 이 값은 `neo-agent/${string}` 템플릿 리터럴 타입으로 **컴파일 타임에 사칭을 막는 값**이다(`ARCHITECTURE.md` §2.2의 실장). 반대 방향(`package.json`을 읽어 코드를 채움)은 불가능하다: `providers`는 예산 게이트가 `node:fs`를 금지하는 패키지이고, 그 금지의 근거가 *"어댑터는 API 키를 파라미터로만 받고 스스로 크리덴셜을 읽지 않는다"*이다. 버전을 읽으려고 파일 읽기를 여는 것은 그 격리를 versioning 편의와 맞바꾸는 것이다.

**동기화는 게이트가 강제한다.** `scripts/check-core-budget.mjs`가 이미 모든 `package.json`을 읽으므로, `registration.ts`의 리터럴과 각 `package.json`의 `version`, shim의 최소 Node 상수와 `engines`가 어긋나면 exit 1로 떨어뜨린다.

이 방식을 고른 근거는 전례다 — devnote 2026-08-09 §9.4가 *"수치의 정본은 예산 게이트 스크립트이고 문장은 그것을 서술한다"*를 CLI 패키지 수에 적용했고, 그 자리는 **사람이 세는 문장이 남아 있어 두 번 어긋났다**. 같은 실패를 버전에서 반복하지 않는다.

**버전의 의미는 semver 계약이 아니다.** 소비자가 본인 하나이므로 major/minor의 호환성 약속에는 수신자가 없다. 실질적 호환성 축은 `LATEST_SCHEMA_VERSION`(`packages/store/src/migrate.ts`)이며, 버전 문자열은 **어느 시점의 코드인지를 가리키는 이름표**다. 따라서 릴리스 절차를 만들지 않는다 — git 태그면 충분하다.

## 5. 갱신과 되돌리기

**갱신 = `git pull` + `pnpm install`(잠금 파일이 바뀐 경우).** 빌드가 없으므로 이것이 전부다.

### 5.1 실행 중 갱신 금지

**소스 트리가 곧 런타임이다.** 세션이 도는 중에 `git pull`을 하면 아직 로드되지 않은 모듈이 새 코드로 들어와 한 프로세스 안에 두 버전이 섞인다. hermes가 정확히 이 함정을 문서화했다 — *"에이전트가 자기 체크아웃에 상대 경로 명령을 실행하면 러닝 런타임을 세션 중에 파괴할 수 있다"*(그래서 venv를 소스 트리 밖에 만들라고 요구한다).

이것은 **강제하지 않고 문서에 적는 운영 규칙**이다. 강제하려면 실행 중 프로세스를 추적해야 하는데, 그 기계(락 파일·PID 추적)는 `SESSION-STORE.md` §9가 *"같은 세션을 두 프로세스가 여는 것은 막지 않는다"*로 이미 물리친 방향이다.

### 5.2 다운그레이드는 지원하지 않는다

`migrate.ts`는 **DB 스키마 버전이 빌드가 아는 최신보다 높으면 기동을 거부**한다. 마이그레이션 규율이 *"앞으로만 간다. 다운그레이드 경로를 만들지 않는다"*(`SESSION-STORE.md`)이므로 이는 설계된 동작이고 옳다. 배포 관점의 귀결을 명시한다:

- 새 버전으로 한 번 기동해 마이그레이션이 적용되면, **옛 커밋으로 되돌려도 그 DB로는 뜨지 않는다.**
- 되돌리는 유일한 방법은 **마이그레이션 이전에 뜬 `~/.neo-agent/sessions.db` 사본**이다.
- 마이그레이션 자체는 트랜잭션 하나이므로 **실패는 전량 롤백**이고, 승격은 통지된다(`SESSION-STORE.md` — 침묵 금지). 즉 위험 구간은 "실패"가 아니라 "성공했는데 새 버전을 물리고 싶을 때"다.

**자동 백업을 만들지 않는다.** 위 구간이 좁고, 백업은 새 기계(회전·정리·경로 설정)를 부른다. README가 갱신 절차에 수동 사본 한 줄을 적는 것으로 대신한다. **재검토 트리거**: 마이그레이션이 데이터를 잃는 형태(컬럼 삭제·손실 변환)를 처음 요구할 때 — 그 마이그레이션과 백업이 함께 와야 한다.

## 6. 설치 트리가 워크스페이스일 때 — 고지하되 막지 않는다 (2026-08-09 확정)

링크 설치의 귀결로 **소스 트리 = 런타임**이므로, neo-agent를 자기 저장소 안에서 실행하면 파일 도구가 닿는 곳이 지금 돌고 있는 코드다.

**판정: 시작 시 고지하고, 막지 않는다.**

- **막지 않는 이유** — neo-agent로 neo-agent를 개발하는 것이 **주 용도**다. 설치 트리를 `TOOLS-INTERFACE.md` §3의 denylist에 넣으면 그 용도가 죽는다. 크리덴셜·메모리 denylist와는 성격이 다르다: 그쪽은 *에이전트가 접근할 이유가 없는* 영역이고, 여기는 *접근하는 것이 목적인* 영역이다.
- **고지하는 이유** — `ARCHITECTURE.md` §2.6. 그리고 이것은 **게이트가 확실히 아는 사실**이다(realpath 둘의 비교). devnote 2026-08-09 §9.11의 판정 기준을 그대로 따른다: *"아는 것은 말하고 모르는 것은 말하지 않는다."*
- **고지 내용은 두 가지 사실이다**: ① 지금 워크스페이스와 neo-agent 자신의 설치 트리가 겹친다 ② 편집한 코드는 **다음 기동부터** 적용된다(이미 로드된 모듈은 바뀌지 않는다). ②를 빠뜨리면 사용자는 고친 것이 왜 안 먹는지 모른다.
- **겹침은 양방향이다** (2026-08-09 구현 중 판정 D-5). 이 절의 첫 문장이 *"자기 저장소 안에서 실행하면"*으로 한 배치만 적었으나, 위험을 만드는 조건은 **파일 도구가 닿는 범위에 돌고 있는 코드가 있는 것**이고 그것은 포함 방향과 무관하게 성립한다. 워크스페이스가 설치 트리를 **품는** 배치 — `/home/x/neo-agent`에서 기동하고 설치 트리가 `/home/x/neo-agent/neo-agent-main`인, **이 저장소의 실제 배치** — 에서도 같은 위험이다. 좁게 구현하면 가장 흔한 경우에 고지가 나가지 않는다. 고지는 경계가 아니므로 넓게 잡아 잃는 것이 없다. 단 **두 배치의 문면은 다르다** — 품는 쪽에는 설치 트리 경로를 함께 말한다(devnote 2026-08-09 §9.11: *"아는 것은 말하고 모르는 것은 말하지 않는다"*).

**판정 방법과 그 한계**:

- 설치 루트는 `main.ts`가 `import.meta.dirname`의 realpath에서 상위 3단계(`packages/cli/src` → 저장소 루트)로 계산해 조립에 주입한다. `WorkspaceBoundary.root`(이미 realpath로 동결)와 **세그먼트 단위**로 비교한다 — 문자열 prefix 비교 금지는 `TOOLS-INTERFACE.md` §3과 같은 이유다.
- **이 경고는 경계가 아니라 고지다.** 레이아웃이 바뀌어 계산이 틀리면 경고가 안 나올 수 있고, 그때도 기동은 정상 진행한다. 대신 **계산된 루트에 `pnpm-workspace.yaml`이 있는지를 테스트가 단정**해 레이아웃 변경이 조용히 경고를 죽이는 것을 막는다.

## 7. TTY 없이 기동하면 거부한다 (`main.ts` `[미규정] R-3`의 해소)

`packages/cli/src/main.ts`와 `CLI-INTERFACE.md` §12에 양쪽으로 등재돼 있던 미규정을 이 문서가 닫는다. **`process.stdin.isTTY`가 아니면 원인과 다음 행동을 담은 에러로 종료한다.**

근거는 `main.ts`에 이미 적혀 있던 것 그대로다 — 승인 게이트가 **물어볼 사람이 없는데 묻는** 상태가 되고, 그 조합의 결말은 조용한 행(hang)이다. `ARCHITECTURE.md` §2.6의 심각도 순서에서 **silent failure가 crash보다 나쁘다**는 것이 이 판정의 전부다.

배포 문서가 이것을 닫는 이유: 설치가 되고 나면 `neo-agent`가 **의도치 않은 맥락에서 실행될 수 있게 된다**(cron 항목의 오타, 스크립트 안의 호출). 레포 안에서만 돌 때는 없던 표면이다.

### 7.1 `CLI-INTERFACE.md` §12가 닫기를 미룬 근거와, 그것이 해소되는 자리

그 문서는 *"지금 닫으면 **스크립트 구동 검증 경로까지 막는다**"*를 이유로 열어 뒀다. 정당한 우려였고, 실측으로 해소된다:

- **검사 위치가 `main.ts`다.** `main.ts`는 `process.*`를 읽는 유일한 곳이고, 조립(`runCli`)은 주입된 스트림만 본다(`CLI-INTERFACE.md` §1의 기존 계약). 테스트·QA는 `runCli`를 **모의 스트림으로 직접** 호출하므로 이 검사를 지나지 않는다.
- **실측**: `packages/cli/test/`의 통합 테스트 전부가 `runCli` 직접 호출이고, 이 판정을 내릴 당시 **실제 bin을 스폰하는 테스트는 0건**이었다. 모의 스트림 경로는 이미 `isTTY !== true`를 정상 분기로 다룬다(`approval-ui.ts:149`, `wiring.ts:1011` — raw 모드 없이 라인 모드로 강등). 그 분기는 **그대로 남는다.**
- **"0건"은 더 이상 참이 아니고, 그것이 개선이다** (2026-08-09 QA-B). 검증에 bin을 스폰하는 테스트가 생겼다 — `main.ts`의 검사를 관측할 다른 수단이 없기 때문이다. 판정의 실체는 *"모의 스트림 경로가 이 검사를 지나지 않는다"*이고 그것은 그대로다. **스폰 테스트의 존재는 그 주장을 깨는 것이 아니라 그 주장을 감시하는 장치다** — TTY 검사를 `runCli` 안으로 옮기면 그 테스트가 빨간불이 된다(QA-B가 변이로 실증).
- **남는 유일한 손실은 "설치된 bin을 파이프로 구동하는 것"인데, 그 경로는 애초에 동작하지 않았다.** `main.ts`가 이미 기록해 둔 사실이다 — 라인 가드의 이스케이프 시퀀스가 파이프로 섞여 나가고, 승인 프롬프트는 raw 모드 없이 Enter를 기다린다. **거부는 기능을 없애는 것이 아니라 이미 깨진 경로를 보이게 만드는 것이다.**

**트리거** — 무인 실행이 실제로 필요해질 때. 그때는 TTY 요구를 푸는 것이 아니라 **승인 모드와 함께** 설계할 문제다(물어볼 사람이 없는 상태에서 무엇을 자동 허용할지가 본체이고, TTY 판정은 그 결과다).

## 8. 공급망 — 표면이 작을 때 싸게 조인다

외부 런타임 의존성은 **2개**(`@anthropic-ai/sdk`, `zod`), 개발 의존성은 **4종**(`@biomejs/biome`, `@types/node`, `typescript`, `vitest`)이다. 이 규모에서는 두 레퍼런스의 방어를 거의 비용 없이 가져올 수 있다.

**✅ 채택**:

- **의존성 정확 핀** — 현재 `^`/`~` 범위를 정확 버전으로 바꾼다. hermes가 *"모든 직접 의존성이 `==X.Y.Z` 정확 핀"*으로 간 계기가 2026-05-12 Mini Shai-Hulud 웜의 PyPI 감염이었다(`docs/hermes-agent-architecture.md` §2.1). 잠금 파일이 재현성을 이미 주지만, 핀은 **`pnpm update`가 조용히 넓게 움직이는 것**을 막는다 — 갱신이 명시적 행위가 된다.
- **`minimumReleaseAge`**(pnpm 워크스페이스 설정) — OpenClaw가 2880분(48시간)으로 쓴다. 침해된 릴리스가 내려가기까지의 창을 넘긴다. 설정 한 줄, 비용 0.
  - **정확 핀과 겹치면 양태가 폴백이 아니라 거부다** (2026-08-09 QA-A 실측). 범위 지정자(`^4.4.3`)라면 성숙한 버전으로 조용히 내려가지만, 우리는 D-2로 **전부 정확 핀**이므로 임계보다 어린 버전을 핀하면 `ERR_PNPM_NO_MATURE_MATCHING_VERSION`으로 **설치가 실패한다.** 즉 **릴리스 48시간 안에는 의존성을 올릴 수 없다.** 이것은 결함이 아니라 두 결정의 의도된 합이지만, 갱신하려다 막히면 원인을 모를 수 있어 여기 적는다.
- **`blockExoticSubdeps`** — git/tarball 출처 하위 의존성 차단. 현재 트리에 없을 것이므로 사실상 무변화이나, **없는 상태를 고정**하는 것이 목적이다.
  - **막는 범위를 정확히 적는다** (2026-08-09 QA-A 실측): git 출처와 원격 tarball URL은 차단되지만 **`file:` 출처 하위 의존성은 차단되지 않는다.** 이름이 "exotic 전부"를 연상시키므로 그 차이를 여기 적어 둔다 — 막지 못하는 것을 막는 것처럼 보이게 두지 않는다(D-3과 같은 규율).
- **`packageManager` 필드로 pnpm 버전 고정** — OpenClaw가 11.15.1로 고정한 것과 같은 이유. 현재 10.34.5.
  - **강제 양태는 거부가 아니라 자동 전환이다** (2026-08-09 T-005 실측). 선언과 다른 pnpm으로 실행하면 pnpm이 선언된 버전을 내려받아 그것으로 실행한다. §8의 목적(버전 고정)은 달성되지만 게이트가 아니라 스위치다.
  - **`+sha512.` 해시를 pnpm은 검증하지 않는다** (같은 실측: 0으로 채운 가짜 해시로도 다운로드·실행됐다). 검증 주체는 corepack인데 **Node v25.9.0 배포에 corepack이 없다.** 해시 값 자체는 실제 배포 tarball의 sha512와 대조해 정확함을 확인했고, corepack이 있는 환경에서는 실효하므로 **필드에 남긴다.** 다만 **이 해시를 무결성 보증으로 서술하지 않는다** — D-3이 죽은 설정 줄에 대해 세운 규율("막지 못하는 것을 막는 것처럼 보이는 표시를 남기지 않는다")이 문장에도 그대로 적용된다.

**설정이 살아 있는지 확인하는 법** — `pnpm-workspace.yaml`의 **오타 키는 경고 없이 무시된다**(2026-08-09 QA-A 실측). 따라서 *"YAML에 줄이 있다"는 설정이 살아 있다는 증거가 아니다.* 확인은 `pnpm config get <key>`로 되묻는 쪽이고, 그것도 미설정과 미지원을 구분하지 못하므로 **최종 근거는 실제 동작**이다. 이 함정 때문에 D-3이 "죽은 줄을 남기지 않는다"를 규율로 세웠다.

**❌ 안 가져올 것**:

- **CI(GitHub Actions) 전반** — OpenClaw 23개 워크플로, hermes의 `osv-scanner.yml`·`supply-chain-audit.yml`. 검증 게이트(`pnpm check`)는 이미 있고 실행 주체가 1명이며, `/execute` 사이클이 매번 통합 게이트를 돌리는 규율이 그 자리를 메우고 있다. **트리거**: 외부 기여 PR이 오거나, 게이트를 안 돌린 푸시 사고가 실제로 날 때.
- **`exclude-newer`류의 시각 기준 고정**(hermes uv) — `minimumReleaseAge`와 목적이 겹친다. 둘 다 넣을 이유가 없다.

## 9. README의 책임 (공개 레포의 정면)

이 설계를 쓸 당시 `neo-agent-main/README.md`는 *"스캐폴딩 전"*이라고 적혀 있었고 이는 **사실이 아니었다**. 공개 레포에 8커밋을 푸시한 상태에서 정면 문서가 틀린 것은 §2.6의 문제이기 이전에 신뢰의 문제다. **2026-08-09 전면 재작성으로 해소됐다** — 적힌 설치 절차를 그대로 실행해 `/tmp`에서 `neo-agent --version`이 도는 것까지 확인했다(**TTY 필요** — §7. 검증은 `script -qec … /dev/null` 경유였다. 재현 절차를 적을 때는 재현 조건도 함께 적는다).

**README가 담는 것**: 무엇인지 한 문단 · 설치·실행(§3.1) · 전제(Node 24+, Docker 유무에 따른 셸 도구 가용 — `SANDBOX.md`) · API 키 설정 위치(`CLI-INTERFACE.md` §4) · 갱신과 되돌리기(§5) · 안전 기본값 한 문단(`SAFE-DEFAULTS.md` 요약 + "유일한 경계는 OS") · 문서 지도.

**README가 담지 않는 것**: 설계 근거. `docs/`가 정본이고 README는 링크만 건다. 근거를 복제하면 두 곳이 어긋나고, 그때 어느 쪽이 최신인지 알 수 없어진다(루트 `CLAUDE.md`의 devlog/devnote 분리와 같은 원리).

**`THIRD_PARTY_NOTICES.md`는 이미 `REUSE-MAP.md` §6.1이 정한 대로 git 루트에 중앙 blanket으로 둔다** — 이 설계가 바꾸지 않는다.
