# neo-agent-main

**neo-agent의 코딩 작업공간.** 모든 소스코드와 자체 아키텍처 문서가 여기 있다.

## 경계

저장소 루트에는 세 종류의 디렉터리가 있고 성격이 전혀 다르다.

| 디렉터리 | 성격 | 수정 |
|---|---|---|
| `neo-agent-main/` (여기) | **우리가 만드는 것** | 자유 |
| `openclaw-main/`, `hermes-agent-main/` | 남의 코드. 참조용 | **금지 — 읽기 전용** |
| 루트의 `docs/`, `devlog.md`, `idea.md`, `devnotes/` | 프로젝트 운영 문서 | 지정된 스킬 경유 |

**루트 `docs/`와 `neo-agent-main/docs/`를 혼동하지 말 것.**
- 루트 `docs/` — 남의 코드를 읽은 결과 (OpenClaw·hermes 분석)
- `neo-agent-main/docs/` — **우리 설계** (`ARCHITECTURE.md`)

## 현재 상태

**스캐폴딩 전.** 기술 스택(TypeScript vs Python)이 정해지지 않아 `src/` 구조를 만들지 않았다. 스택이 확정되면 그때 잡는다.

지금 있는 것은 `docs/ARCHITECTURE.md` 하나이며, 스택과 무관하게 확정된 설계 원칙과 아직 열려 있는 결정을 담고 있다.

## 코드를 쓰기 시작할 때

1. `docs/ARCHITECTURE.md`의 설계 원칙을 먼저 읽는다. 특히 **경계 규칙**(에이전트 코어는 전송 계층을 모른다)과 **컴플라이언스 게이트**는 나중에 되돌리기가 매우 어렵다.
2. 루트 `CLAUDE.md`의 "컴플라이언스 — 이식 금지 목록"을 확인한다. 모델 인증 코드를 쓸 때는 반드시.
3. 레퍼런스에서 가져올 것이 있으면 **복사하지 말고 이해 후 재작성**한다. 두 레퍼런스의 코드는 그 프로젝트의 제약(플러그인 SDK 하위호환, 채널 27종, 멀티프로파일) 아래 쓰였고 개인용 에이전트에는 대부분 불필요하다.
